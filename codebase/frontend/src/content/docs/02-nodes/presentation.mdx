이 페이지에서는 워크플로우의 결과를 **시각화**하거나 **사용자 입력**을 받는 프레젠테이션 노드 다섯 가지를 설명해요. Carousel·Table·Chart·Template은 버튼을 달아 Human-in-the-loop로 동작시킬 수도 있고, Form은 기본이 블로킹 입력 노드예요.

## 공통 패턴 — 버튼과 블로킹 모드

## Chart

### 언제 쓰나요?

- 숫자 데이터를 **바·라인·파이·도넛·면적** 차트로 시각화하고 싶을 때 써요.
- 바·라인·면적 차트에서는 `groupBy`로 시리즈를 나눠 여러 시리즈를 한 차트에 그릴 수 있어요.
- `yAxis.aggregation`을 정하면 X축 값이 같은 행의 Y값을 합산·평균 등으로 집계해요. 정하지 않으면 집계하지 않고 입력 행을 그대로 그려요.

### Aggregation 규칙

`yAxis.aggregation`을 정하면 X축 값이 같은 행끼리 묶어서 Y값을 집계해요. `groupBy`를 쓰면 X축 값과 시리즈가 모두 같은 행끼리 묶어요.

<FieldTable rows={[
  {name: "정하지 않음", required: false, type: "집계 없음", description: "집계하지 않고 입력 행의 값을 그대로 써요. 기본 집계는 없어요. 설정 화면의 드롭다운에서는 **없음 (원래 값)** 이에요.", default: "-"},
  {name: "sum", required: false, type: "합계", description: "같은 묶음의 Y값을 합산해요. 알 수 없는 `aggregation` 값도 sum으로 처리해요.", default: "-"},
  {name: "count", required: false, type: "행 수", description: "같은 묶음에 속한 행 수를 세요. Y값이 null이어도 세요.", default: "-"},
  {name: "avg / min / max", required: false, type: "평균/최소/최대", description: "같은 묶음의 Y값으로 평균·최솟값·최댓값을 구해요.", default: "-"}

숫자로 바꿀 수 없는 Y값과 null·undefined는 건너뛰지 않고 **0으로 바꿔서** 집계에 넣어요. avg의 분모에도 들어가요. X축 값이 없는 행도 X축 값이 비어 있는 묶음으로 남아요. 이런 행을 빼고 싶으면 Chart 앞에 [Filter](/docs/02-nodes/logic#filter) 노드를 둬요.

### 시리즈와 색

**시리즈 나누기 (`groupBy`)**

- 바·라인·면적 차트에서 `groupBy`를 정하면 각 항목의 그룹 필드 값을 문자열로 바꿔 시리즈 이름으로 써요. `output.data`의 포인트마다 `series`가 붙고, 시리즈는 `output.data` 한 배열에 함께 담겨요.
- 시리즈마다 막대·선·면이 하나씩 그려지고 범례에 시리즈 이름이 표시돼요. X축 값과 시리즈는 입력에서 처음 나온 순서대로 놓여요.
- 그룹 값이 null이거나 없는 항목은 이름이 빈 시리즈로 묶여요. 범례에는 "(빈 값)"으로 보여요.
- 집계는 (시리즈, X축 값) 묶음마다 해요. 집계를 정하지 않았는데 같은 (시리즈, X축 값)이 여러 번 나오면 마지막 값을 그려요. 값을 모두 반영하려면 `aggregation`을 정해요.
- 파이·도넛 차트는 `groupBy`를 쓰지 않아요. 설정 화면에서 **그룹 기준** 입력이 숨겨지지만 저장된 값은 남아 있어요. 차트 유형을 다시 바·라인·면적으로 바꾸면 그 값이 다시 쓰여요.

**색 (`colors`)**

- 바·라인·면적 차트는 i번째 시리즈에 `colors`의 `i % 색 개수` 번째 색을 써요. 시리즈가 하나면 모든 막대가 첫 번째 색이에요.
- 파이·도넛 차트는 조각마다 `colors`를 차례로 돌려 써요.
- 색은 `#3B82F6` 같은 16진수, `rgb()`·`rgba()`·`hsl()`·`hsla()`, `red` 같은 색 이름만 쓸 수 있어요. 다른 형식의 값은 건너뛰어요.
- `colors`가 비어 있거나 쓸 수 있는 색이 하나도 없으면 기본 팔레트를 같은 규칙으로 써요.

### 예시

<Example title="월별 매출 바 차트">
```ts
// config
{
  chartType: "bar",
  title: "Monthly Revenue",
  dataField: "sales",
  xAxis: { field: "month", label: "월" },
  yAxis: { field: "revenue", label: "매출", aggregation: "sum" },
  groupBy: "region",
  colors: ["#3B82F6", "#10B981"]
}
```
</Example>

이 설정은 입력 객체의 `sales` 배열을 월(`month`)별로 묶어 합산하고, `region` 값마다 막대 시리즈를 하나씩 만들어요. 첫 번째 시리즈는 `#3B82F6`, 두 번째 시리즈는 `#10B981`로 그려져요.

<Example title="groupBy로 지역별 시리즈 만들기">
```ts
// 입력
{
  sales: [
    { month: "Jan", region: "Seoul", revenue: 700 },
    { month: "Jan", region: "Seoul", revenue: 500 },
    { month: "Jan", region: "Busan", revenue: 800 },
    { month: "Feb", region: "Seoul", revenue: 1500 },
    { month: "Feb", region: "Busan", revenue: 900 }
  ]
}

// config
{
  chartType: "line",
  dataField: "sales",
  xAxis: { field: "month" },
  yAxis: { field: "revenue", aggregation: "sum" },
  groupBy: "region"
}

// output.data: (시리즈, X) 묶음마다 합산한 포인트를 한 배열에 담아요
[
  { x: "Jan", y: 1200, series: "Seoul" },
  { x: "Jan", y: 800, series: "Busan" },
  { x: "Feb", y: 1500, series: "Seoul" },
  { x: "Feb", y: 900, series: "Busan" }
]
```
</Example>

`groupBy`를 쓰면 포인트에 `series`가 붙어요. 노드 이름이 `Chart`일 때 `{{ $node["Chart"].output.data[1].series }}`는 `"Busan"`이고 `{{ $node["Chart"].output.data[1].y }}`는 `800`이에요. `groupBy`를 비워 두면 `series` 없이 `{ x, y }` 포인트만 나와요.

- 실행이 일시 정지되고, 폼이 제출되면 검증 통과 시 재개돼요.

## AI 도구 모드 (Presentation Tools)

이 카테고리의 노드 5종 (Carousel / Table / Chart / Form / Template) 의 input schema 는 AI Agent 의 `presentationTools` 설정에서 LLM tool parameters JSON Schema 의 단일 진실로 재사용돼요.

즉, 워크플로우 그래프에 Presentation 노드를 직접 연결하지 않아도, AI Agent 가 `presentationTools` 를 등록하면 LLM 이 판단에 따라 채팅 UI 안에서 동일한 렌더링을 직접 만들 수 있어요.

**동작 요약:**

- `render_table` / `render_chart` / `render_carousel` / `render_template` — display-only. 워크플로우 실행을 종료하지 않고 LLM 응답에 inline 렌더돼요.
- `render_form` — interactive. Multi Turn 모드에서 사용자에게 폼을 표시하고 응답을 대기해요. Single Turn 모드에서는 무시돼요.
- `defaults` overlay: AI Agent 설정의 `defaults` 필드로 columns·buttons·layout 등 brand/style 고정값을 지정하면, LLM 이 생성한 페이로드와 deep-merge 시 `defaults` 가 우선해요.
- 1 MB cap: Carousel·Table 은 tail truncate, Chart·Template 은 초과 시 silent drop 이에요.
- schema 위반: 1회 재시도 후 silent drop. `error` 포트는 발화하지 않아요.

자세한 동작 (defaults overlay, 1 MB cap, schema 위반 폴백) 은 [AI 노드 §Presentation Tools](/docs/02-nodes/ai#presentation-tools) 를 참고해요.

## 캔버스 요약

- Carousel: `{layout} · {titleField}` 또는 `{layout} · {N} buttons`
- Table: `{N} columns · pagination` 또는 `{N} columns · {N} buttons`
- Chart: `{chartType} · {xAxis.field} / {yAxis.field}` 또는 `{chartType} · {N} buttons`
- Form: `{N} fields · "{title}"`
- Template: `{outputFormat} · {N} lines` 또는 `{outputFormat} · {N} buttons`

## 팁 & 참고

- 실행 결과 드로어에서 각 프레젠테이션 노드가 어떻게 렌더링되는지는 [실행 결과](/docs/05-run-and-debug/run-results)에서 다뤄요.
- 버튼 블로킹·폼 대기·AI 대화가 섞인 워크플로우에서 실행 상태가 `waiting_for_input`으로 바뀌면, 사용자가 버튼을 누르거나 폼을 제출하기 전까지 실행이 일시정지돼요. 사용자의 응답이 들어오면 자동으로 이어서 실행돼요.
- 파워유저 팁: 버튼이 있는 Presentation 노드는 버튼마다 전용 출력 포트가 자동으로 생겨요. 사용자가 누른 버튼의 포트로만 흐름이 이어지므로, 버튼별 후속 동작을 분기해서 디자인할 수 있어요.

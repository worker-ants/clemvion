This page covers how to centrally manage your third-party integrations. Nodes like HTTP Request and Send Email reuse the integrations you create here.

## What an integration is

An integration is a bundle of credentials for reaching an external service. Create one, and multiple nodes across multiple workflows can share the same account/key. Key rotation and re-auth happen in one place.

## Sharing inside a team workspace

Integrations created with Organization scope in a team workspace are automatically usable by every member. Integrations created with Personal scope in the same team workspace, though, are visible only to the person who created them — other members can't find them in the list or even by navigating straight to the detail page, and the rule has no role exception: Owners and Admins can't see another member's Personal integrations either. Switching workspaces from the sidebar refreshes the integration list for the selected workspace.

<Callout type="tip">Integrations in a personal workspace are visible only to the owner. To share with a team, create the integration inside the team workspace. The same external account is a separate record per workspace.</Callout>

## Adding an integration

Click `[+ Add Integration]` in the top-right of [Integrations](/integrations). Pick a service in the modal; the flow then transitions into a dedicated page starting from the auth step (`/integrations/new?service=...&step=auth`).

<Steps>
<Step>In the service-picker modal, click one of Google, GitHub, HTTP, Database, Email, Webhook.</Step>
<Step>In Step 2, set an alias (`name`) and scope (Personal / Organization). In a team workspace, only admins can pick Organization scope.</Step>
<Step>Enter service-specific credentials. OAuth services use scope checkboxes; click `[Connect with ...]` to authenticate through a popup.</Step>
<Step>Step 3 auto-runs `POST /api/integrations/preview-test`. `[Save integration]` activates once the test passes.</Step>
<Step>On save, you're redirected to the detail page (`/integrations/[id]`) with an `Integration created` toast.</Step>
</Steps>

<Callout type="warn">If the OAuth popup doesn't return within 5 minutes, the attempt times out. The credentials you entered aren't restored for safety reasons — restart from Step 2.</Callout>

<Callout type="note">
What a connection test checks depends on the service.

- **Actually connects**: Email (through SMTP login), MCP server, Database, HTTP/REST.
- **Checks input format only** (no external call): Google, GitHub, Webhook.
- **Cafe24 · MakeShop**: format-only while adding the integration (Step 3); once connected, `Test connection` on the detail page makes a real call.

Database opens a connection and runs `SELECT 1`. A wrong password or missing access privileges fail the test, and the test connection closes right after. HTTP/REST sends a request to `base_url` using the same credentials the node would use — only a 401 or 403 response confirms the credentials are wrong. Other 4xx responses count as a pass (the server was reachable) but don't confirm the credentials are correct, and a 5xx response fails. If `base_url` is empty (the node supplies the full URL instead), no request is sent. Database waits up to 10 seconds each for the connection and for `SELECT 1`; HTTP/REST waits up to 10 seconds for the whole request, redirects included.

Database, HTTP and Email (SMTP) connections aimed at private, loopback or CGNAT (`100.64.0.0/10`) addresses are blocked for security, and the test fails (unless the operator has allowed internal addresses for the installation). Nodes that use the integration in a workflow are blocked by the same rule. The blocked address is not shown in the error message.
</Callout>

<Callout type="tip">When an integration flips to `expired` or `error`, the sidebar shows an attention badge and the list displays a `Need attention` banner. Clicking it jumps to the matching status filter. Attention also includes `connected` integrations whose token expires soon (within 7 days). **Note: integrations that support refresh_token auto-renewal (Cafe24, MakeShop, Google) are NOT included in the `Need attention` banner, sidebar badge, or `Expiring` filter even when expiry is near** — the system renews them automatically in the background, so no action is needed (for the same reason, no passive `integration_expired` notification is sent when the access_token expires). If auto-renewal fails and the integration flips to `error`/`expired`, it then appears in attention as usual and an `integration_action_required` active alert is sent.</Callout>

## Choosing an integration from a node

In the workflow editor, adding an HTTP Request, Send Email, or Database Query node exposes an `Integration` dropdown at the top of the settings panel. The dropdown lists only integrations whose service type matches.

<Example title="Using an integration from an HTTP Request node">
```ts
// The values you pick in the settings panel are persisted in the node config.
{
  "type": "httpRequest",
  "config": {
    "integrationId": "int_01H...",   // integration id from integration management
    "method": "POST",
    "path": "/v1/orders",            // relative path joined to base_url
    "body": "{{ $run.input }}"
  }
}
```
</Example>

Send Email works the same way. The SMTP integration's `default_from` becomes the default sender; each node can still override it.

## Tips & notes

- Credentials are stored encrypted with AES-256-GCM. API responses return only masked previews like `****4f2a`.
- For non-OAuth integrations, `Rotate credentials` only overwrites the existing secret after the new value passes the connection test. On failure, the existing credential is untouched.
- To register multiple accounts for the same service, add separate integrations with different aliases. Aliases must be unique within a workspace.
- An integration in use cannot be deleted. Clicking `Delete integration` first checks its usages; if it's still in use, a delete-blocked dialog shows which workflows and nodes reference it (AI Agent MCP-server references are marked with an `MCP` badge). Follow the workflow link in the dialog, switch the node's `integrationId` to another integration or remove the node, then delete again.
- To expose external tools and resources to the LLM from an AI Agent, register an MCP server integration and wire it into the AI Agent node's `MCP Servers` field. See [MCP server integration](/docs/06-integrations-and-config/mcp-servers).

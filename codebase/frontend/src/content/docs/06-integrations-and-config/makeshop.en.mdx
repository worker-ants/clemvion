This page walks you through registering a Korean e-commerce SaaS **MakeShop** store as an integration and using it from both workflow nodes and the AI Agent.

## Why use the MakeShop integration?

- **One credential, two surfaces** — A single MakeShop integration is usable from both (a) the `MakeShop` node on the workflow canvas and (b) the AI Agent node's MCP tools. Token refresh and activity logs are unified across both paths.
- **Full coverage of 7 resources** — Call all 161 Shop API operations across Store settings, Product, Order, Member, Benefit, Board, and CPIK from one metadata-driven node. Common tasks take just two dropdowns: Resource → Operation.
- **Natural-language calls from the AI Agent** — Through an in-process Internal MCP Bridge, the LLM turns a natural-language instruction like `"fetch last week's new orders"` into the right endpoint call automatically.

## Creating a MakeShop integration

MakeShop is an **install-first confidential client**. We cannot initiate the OAuth flow ourselves — it starts when the MakeShop ShopStore app install calls our App URL. (Same structure as a Cafe24 Private app.)

### 1) Pick MakeShop in the Add-Integration modal

Sidebar **Integrations** → **+ Add integration** → click the **🛒 MakeShop** card → go to the MakeShop creation form.

### 2) Create your app in Partner Center first

You first need a `client_id` / `client_secret` issued by MakeShop Partner Center.

1. Sign in to MakeShop Partner Center with your store operator account.
2. Go to the **ShopStore app** registration menu and create a new app.
3. Note the issued `client_id` / `client_secret` (used in the next step).

### 3) Step 1 — Enter credentials

In the creation form, enter:

| Field | Value |
|---|---|
| **Integration name** | Free text — e.g. `My MakeShop Store` |
| **Client ID** | The `client_id` issued in Partner Center |
| **Client Secret** | The `client_secret` issued in Partner Center (masked on save) |
| **Scopes** | Check read/write per resource you plan to call. Six groups — `store` · `product` · `order` · `member` · `board` · `benefit` — each split into read/write |

You do **not** enter the store identifier (**shop_uid**). It is delivered automatically via the install redirect when the ShopStore app is installed.

### 4) [Connect with MakeShop] — register App URL + wait for install

After Connect, the integration is created in a **pending** state and two URLs appear:

| URL | Where to register |
|---|---|
| **App URL** | The **App URL** field of your ShopStore app in Partner Center. **Copy the whole value** including the trailing install token (don't hand-type it). |
| **Redirect URI** | The **Redirect URI** field in Partner Center. Must match exactly (trailing slash / `http` vs `https` / port / typos all exact). |

After registering both URLs, install the app from your store. The install redirect calls the App URL and completes OAuth. This screen **auto-polls** for install completion and routes to the integration detail page once connected. If it doesn't connect within 10 minutes you'll see a "still pending" notice (the integration remains on the backend, and polling resumes when you reopen or refresh).

**When an integration is already waiting for install:**
If an integration in the same workspace with the same `client_id` is already waiting for install, the service reuses it instead of creating another one. What happens depends on who started it.

- **A personal integration you started**: you continue with that integration.
- **A personal integration another member started**: you can't add one. A toast reads "Another member's MakeShop install for this client_id is still pending." followed by "Try again after (time)." The time is that install's deadline, 24 hours after the App URL was issued. Once the deadline passes and the pending install expires, you can add the integration again.
- **A pending install started as an Organization integration**: only Admins and above can continue it. Below Admin, a toast reads "Only Admins and above can add or change organization integrations."

A reused integration keeps its scope. If that differs from the scope you asked for, a notice reads "Continuing an integration that was already waiting for install. Its scope stays Organization." where "Organization" is replaced by that integration's scope (Personal or Organization).

**A pending install that passed its deadline:**
If you don't finish installing the app from ShopStore within 24 hours of the App URL being issued, the integration changes to expired (install deadline passed). At that moment it also lets go of the store it was holding.

- **You can register the same store again.** You don't have to delete the expired integration first. Register the same store as a new integration. The expired integration isn't deleted automatically and stays flagged as needing attention, so delete it yourself if you don't need it.
- **The old App URL (install link) no longer works.** Opening the App URL of an expired integration shows an error saying the install link is not valid. Registering again gives you a new App URL.
- **The integration name is kept.** If you register again with the same name as the expired integration, the add-integration screen shows "An integration with this name already exists. Enter a different name." under the name field, and a toast with the same message appears. Change the name and the field error goes away.
- **Expired or errored for another reason is an exception.** An integration for the same store that expired or errored for a reason other than the install deadline (a token expiry, for example) keeps holding the store. The install step stops with an error that the store is already connected. A MakeShop integration can't be reauthorized, so delete it and register again.

## Using it in a workflow — the `MakeShop` node

Drop a `MakeShop` node on the canvas and in its config panel:

1. **Integration** — pick the MakeShop integration you created.
2. **Resource** — choose Store settings / Product / Order / Member / Benefit / Board / CPIK.
3. **Operation** — pick from the resource's operation dropdown. Shown with human-friendly labels.
4. **Fields** — the chosen operation's required/optional fields expand automatically. Every value supports expressions like `{{ $input.x }}`.
5. (When the operation is paginated) **Limit / Offset** inputs appear as well. MakeShop pages by page number, so enter an Offset that is a multiple of Limit. At run time it is converted to page = Offset / Limit + 1. For example, Limit 50 with Offset 100 is page 3. If the Offset is not a multiple, the node routes to the `error` port with `MAKESHOP_INVALID_PAGINATION` before any call is made.

Unlike Cafe24, MakeShop has **no partner-approval markers (⚠)** — every operation is exposed the same way.

## Using it from the AI Agent — MCP tools

Add the MakeShop integration under the AI Agent node's **MCP servers** picker, and the LLM can call the Shop API in natural language. After adding it, expand **Operations allowlist** to check which operations are allowed per resource category. With all checked every operation is allowed; check a subset to restrict the LLM to just those.

## Recommended OAuth scope presets

Start with read-only scopes and add write scopes as needed.

- **Product read automation**: `product.read` (+ `order.read` if needed)
- **Order processing**: `order.read` · `order.write`
- **Member/benefit management**: `member.read` · `benefit.read` (+ write if needed)

## Token refresh and expiry

MakeShop is a **refresh-capable** integration that supports `refresh_token`. This means its expiry handling differs from standard OAuth integrations.

| Situation | Behaviour |
|---|---|
| Has `refresh_token` + `access_token` expired | The system automatically renews the `access_token`. **No expiry notification is sent.** |
| Automatic renewal fails (e.g. refresh_token invalidated) | The integration status transitions to `error` and an `integration_action_required` alert is sent. MakeShop integrations cannot be reauthorized, so delete the integration from [Integrations](/integrations) and register it again. |
| `access_token` expires without a `refresh_token` | The integration status transitions to `expired` and an `integration_expired` alert is sent. |

<Callout type="note">A MakeShop integration that holds a refresh_token will not show a sidebar badge or send a notification when the access_token expires — the system is renewing it automatically in the background. A notification is sent only if automatic renewal fails. In that case, delete the integration and register it again.</Callout>

### Reauthorizing and adding scopes are not supported

MakeShop integrations support neither reauthorization nor adding scopes (Request scopes). On the integration detail page, the **Reauthorize** button on the **Security** tab and the **Request scopes** button on the **Scope** tab are disabled, with the reason shown next to them.

To recover, delete the integration and register it again. An integration that expired because its install deadline passed is the exception. Register the same store again; you don't need to delete that integration first. See "A pending install that passed its deadline" above. If you need more scopes, register it again with every scope you need ticked. Registering again repeats the original flow: put the new App URL into MakeShop Partner Center and install the app from ShopStore.

<Callout type="warn">Reinstalling the app from ShopStore does not restore an integration that has already finished installing (connected, error, or expired). The install link only takes you to that integration's detail page. An integration still waiting for its first install (`pending_install`) continues when you install the app from ShopStore.</Callout>

## FAQ

- **Where do I enter shop_uid?** — You don't. It arrives automatically when the app is installed.
- **It won't connect** — Verify the App URL / Redirect URI are registered exactly in Partner Center, including the trailing install token. A single mismatched character fails HMAC verification and the call is rejected.
- **How do I reauthorize?** — MakeShop integrations cannot be reauthorized. Delete the integration and register it again. For an integration that expired because its install deadline passed, register the same store again; you don't need to delete that integration first. Reinstalling the app from ShopStore does not restore an integration that is already connected.
- **I need more scopes** — MakeShop integrations cannot be granted new scopes. Tick every scope you need, delete the integration, and register it again. For an integration that expired because its install deadline passed, register the same store again; you don't need to delete that integration first.
- **I didn't receive an expiry notification — why was my connection disrupted?** — No notification is sent while automatic renewal is succeeding. An `integration_action_required` alert is sent only when automatic renewal fails. See the recovery entry above.

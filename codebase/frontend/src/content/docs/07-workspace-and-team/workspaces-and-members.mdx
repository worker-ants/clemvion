워크스페이스는 워크플로우 · Integration · 지식 베이스가 묶이는 단위예요. 혼자 쓰는 **개인 워크스페이스**와 여러 명이 함께 쓰는 **팀 워크스페이스** 두 가지가 있고, 사이드바 하단의 사용자 메뉴에서 언제든 전환할 수 있어요.

## 개인 vs 팀

| 구분 | 개인 워크스페이스 | 팀 워크스페이스 |
| ---- | ----------------- | --------------- |
| 멤버 수 | 1명 (본인) | 여러 명 |
| 자동 생성 | 첫 가입·이메일 인증 시 1개가 자동 생성 | 사용자가 직접 만든다 |
| 멤버 관리 | 없음 | Admin+ 가 초대/역할 변경/제거 (Admin 역할을 주거나 바꾸는 일은 Owner 만) |
| 공유 워크플로우 표시 | 없음 (모두 내 것) | 모든 워크플로우에 `Team` 배지 |
| Owner 이양·삭제 | 없음 (탈퇴=계정 삭제) | Owner 가 이양 또는 삭제 가능 |

> 초대 토큰으로 가입한 사용자는 **개인 워크스페이스가 자동 생성되지 않아요**. 초대된 팀 워크스페이스가 첫 컨텍스트가 되고, 필요하면 워크스페이스 관리 화면에서 직접 만들 수 있어요.

## 팀 워크스페이스 만들기

1. 사이드바 사용자 아바타 클릭 → 워크스페이스 섹션의 `+ 새 워크스페이스`.
2. 이름을 정하고 만들면 자동으로 본인이 **Owner** 가 돼요.
3. 워크스페이스가 전환되고, 좌측 사이드바 메뉴가 새 컨텍스트에 맞춰 갱신돼요.

## 역할 (RBAC)

| 역할 | 권한 요약 |
| ---- | --------- |
| **Owner** | 모든 권한 + Admin 역할 부여·변경 + 워크스페이스 삭제·소유권 이양 |
| **Admin** | 멤버 초대/제거, 설정 변경, 모든 리소스 CRUD (Admin 역할을 주거나 바꾸는 일은 제외) |
| **Editor** | 워크플로우·트리거·스케줄 CRUD + 실행 |
| **Viewer** | 모든 리소스 읽기 전용 |

통합(Integration)은 이 표에 예외가 있어요. Personal 범위로 만든 통합은 만든 사람에게만 보이고 Owner·Admin 도 볼 수 없어요. 반대로 Viewer 도 자신의 Personal 통합은 재인증하고 scope 추가를 요청할 수 있어요. 자세한 권한은 [통합 관리](/docs/06-integrations-and-config/integration-management)에서 확인해요.

역할별 권한 매트릭스는 워크스페이스 관리 화면 안내에서 확인할 수 있어요.

### Admin 역할은 Owner 만 주고 바꿔요

멤버를 Admin 으로 올리거나 Admin 을 다른 역할로 내리는 일은 **Owner 만** 할 수 있어요.

- **Owner 만 할 수 있는 일**: 멤버를 Admin 으로 변경, Admin 을 다른 역할로 변경, Admin 역할로 초대 (대기 중인 Admin 초대를 다른 역할로 바꿔 다시 초대하는 일도 포함).
- **Admin 도 할 수 있는 일**: 멤버를 Editor 와 Viewer 사이에서 변경, Editor·Viewer 로 초대, 멤버 제거 (제거 규칙은 그대로예요).
- 이미 Admin 인 멤버와 대기 중인 Admin 초대는 이 규칙으로 바뀌지 않고 그대로 유지돼요.

## 멤버 초대하기

/>

**워크스페이스 관리 → 멤버** 탭에서 `[email@…] [Role ▼] [초대]` 폼을 사용해요. 두 가지 경로가 있어요:

- **이미 가입한 사용자** — 이메일이 일치하면 즉시 멤버로 추가되고, 알림이 전송돼요.
- **미가입자** — 7일 유효한 초대 토큰이 메일로 발송돼요. 수신자가 가입을 마치는 순간 자동으로 워크스페이스에 합류해요.

Owner 가 아닌 Admin 에게는 역할 목록에 **관리자** 항목이 나타나지 않아요. 멤버 목록의 역할 드롭다운도 마찬가지고, Admin 멤버의 역할은 바꿀 수 없는 배지로만 보여요. 폼 아래에는 "관리자 역할은 소유자만 주거나 바꿀 수 있어요." 안내가 표시돼요.

대기 중 초대 목록에는 만료 시각이 함께 표시되고, 각 행에서 다음을 할 수 있어요:

- `재발송` — 기존 토큰을 즉시 무효화하고 새 토큰으로 메일을 다시 보내요. 만료 시계도 발송 시점부터 다시 7일.
- `초대 취소` — 대기 중 초대를 폐기해요. 이미 수락된 초대는 취소할 수 없어요.

> 같은 이메일을 다시 초대하면 기존 토큰이 자동으로 무효화되고 새 토큰이 발급돼요 — 다중 토큰이 동시에 살아있지 않도록 단일 초대 row 를 유지해요.

메일의 `초대 수락하기` 버튼을 누르면 로그인 상태와 계정 유무에 따라 가입 화면, 로그인 화면, 초대 수락 화면 중 하나가 열려요.

- **미가입자**: 이메일이 prefill 되고 잠겨 있어요 (다른 이메일로는 가입할 수 없어요 — 이는 토큰 누출 시 권한 escalate 를 차단하기 위한 의도적 제약). 비밀번호·이름만 입력하면 가입과 동시에 워크스페이스에 자동 합류, 곧바로 대시보드로 이동해요. **별도 이메일 인증 단계는 없어요** — 토큰 자체가 이메일 소유 증명이거든요.
- **로그인하지 않은 기존 가입자**: 초대받은 이메일로 이미 가입한 계정이 있으면 가입 화면 대신 [로그인](/login) 화면으로 이동해요. "이미 가입된 이메일이에요. 로그인하면 초대를 수락할 수 있어요." 안내가 잠깐 표시되고, 로그인 화면에는 "로그인하면 초대 수락 화면으로 이동해요." 문구가 보여요.
- **이미 로그인한 사용자**: 링크를 열면 바로 초대 수락 화면이 열려요. 로그인한 계정의 이메일이 초대받은 이메일과 같으면 `수락` 버튼으로 합류해요. 다른 계정으로 로그인한 상태라면 안내 메시지와 `다른 계정으로 로그인` 버튼이 나타나요. 버튼을 누르면 로그아웃되고 로그인 화면으로 이동해요. 초대받은 계정으로 로그인하면 같은 초대 수락 화면으로 돌아와요.
- **만료/이미 사용된 토큰**: 가입 페이지에 안내 배너가 표시돼요. 워크스페이스 Admin 에게 재발송을 요청해 주세요.

### 로그인 뒤 초대 수락 화면으로 돌아오기

초대 링크로 들어와 로그인하면 초대 수락 화면으로 돌아와요. 비밀번호, 2단계 인증, Google · GitHub 로그인 모두 마찬가지예요. 로그인만으로 초대가 수락되지는 않아요. 돌아온 화면에서 `수락` 을 눌러야 워크스페이스에 합류해요.

가입 화면 아래의 `로그인` 링크도 초대 링크로 들어온 경우에는 로그인 뒤 초대 수락 화면으로 돌아와요.

<Callout type="note">
  이메일 인증을 마치지 않은 기존 계정은 로그인할 수 없어요. 인증 메일을 먼저 처리해 인증을 마친 다음, 초대 메일의 `초대 수락하기` 버튼을 다시 눌러요.
</Callout>

## 공유 워크플로우 (Team 배지)

팀 워크스페이스로 전환하면 워크플로우 목록의 모든 항목에 `👥 Team` 배지가 붙어요. 이는 "이 워크플로우는 같은 팀의 다른 멤버가 보고 편집할 수 있다" 라는 시각적 표시예요. 개인 워크스페이스에서는 배지가 보이지 않아요.

### 소유 필터

팀 워크스페이스에서는 검색 우측에 `전체 / 내 워크플로우 / 공유된 워크플로우` 세 가지 필터 그룹이 추가로 나타나요. 같은 팀 안에서 "내가 만든 것" 과 "남이 만든 것" 을 분리해 보는 데 써요. 개인 워크스페이스에서는 이 그룹이 비노출돼요.

## 워크스페이스 설정

워크스페이스 관리 화면의 **설정** 탭에서 기본 동작을 조정할 수 있어요.

### 기본 타임존

스케줄을 만들 때 타임존을 따로 지정하지 않으면 워크스페이스에 설정된 **기본 타임존**이 사용돼요. IANA 식별자(예: `Asia/Seoul`, `America/New_York`) 형식으로 지정하며, 설정하지 않으면 `Asia/Seoul` 이 기본값이에요.

설정 화면의 **개요** 탭에 있는 **기본 시간대** 카드에서 IANA 식별자를 입력해 저장할 수 있어요. 편집은 Admin 이상만 가능하고, 조회는 모든 멤버가 할 수 있어요. 입력란을 비우고 저장하면 워크스페이스 기본 시간대 설정이 해제돼요.

## 워크스페이스 떠나기·삭제

- **나가기** (`위험 영역` 탭) — 본인 멤버십만 제거해요. 유일한 Owner 라면 차단되니, 먼저 [Owner 이양] 으로 다른 멤버에게 권한을 넘기거나 [워크스페이스 삭제] 를 사용해야 해요.
- **Owner 이양** — 같은 워크스페이스의 비-Owner 멤버 한 명을 골라 권한을 넘겨요. 트랜잭션 내에서 두 멤버의 역할이 동시에 swap (대상 → Owner, 기존 → Admin) 돼요.
- **삭제** — Owner 만 가능. 이름을 재입력해 확인하면 멤버·초대·워크스페이스가 트랜잭션으로 정리돼요.

A workspace is the unit that bundles your workflows, integrations, and knowledge bases. You can have a **personal workspace** (just you) or a **team workspace** (multiple members), and you can switch any time from the sidebar's user menu.

## Personal vs team

| | Personal workspace | Team workspace |
| --- | ------------------ | --------------- |
| Members | 1 (you) | Many |
| Auto-created | Yes — on first sign-up + email verification | Created manually |
| Member management | Not applicable | Admin+ invites / changes roles / removes (only the Owner grants or changes the Admin role) |
| Shared-workflow badge | None | `Team` badge on every workflow |
| Owner transfer / delete | Not applicable (leaving = deleting your account) | Owner can transfer or delete |

> Users who sign up via an invitation token **do not get a personal workspace auto-created**. The invited team workspace is their first context. They can create a personal workspace later from the workspace management screen.

## Creating a team workspace

1. Click your avatar in the sidebar → `+ New workspace` in the workspace section.
2. Pick a name. You'll automatically be the **Owner**.
3. The workspace switches over and the sidebar menus refresh to match.

## Roles (RBAC)

| Role | Summary |
| ---- | ------- |
| **Owner** | All permissions + grant/change the Admin role + workspace delete · ownership transfer |
| **Admin** | Invite/remove members, change settings, full resource CRUD (except granting or changing the Admin role) |
| **Editor** | Workflows/triggers/schedules CRUD + execution |
| **Viewer** | Read-only on all resources |

Integrations are an exception to this table. An integration created with Personal scope is visible only to the person who created it — Owners and Admins can't see it either. Adding an integration, and editing, re-authenticating, or requesting scopes on a Personal integration, take an Editor or above. Adding or changing an Organization integration, and switching an integration between Personal and Organization, take an Admin or above. A Viewer can view integrations and test their connection, and can delete a Personal integration they created. See [Integration management](/docs/06-integrations-and-config/integration-management) for the full permissions.

The full role/permission matrix is available in the workspace settings screen.

### Only the Owner grants or changes the Admin role

Promoting a member to Admin or moving an Admin to another role is **Owner-only**.

- **Owner only**: change a member to Admin, change an Admin to another role, invite someone as Admin (including re-inviting over a pending Admin invitation with a different role).
- **Admins can still**: change members between Editor and Viewer, invite Editors and Viewers, and remove members (removal rules are unchanged).
- Existing Admins and pending Admin invitations are left as they are and are not changed by this rule.

## Inviting members

Use the `[email@…] [Role ▼] [Invite]` form on the **Workspace settings → Members** tab. Two paths:

- **Already signed up** — They're added as a member immediately, and notified.
- **Not yet signed up** — A 7-day invitation token is emailed. The moment they finish signing up, they're auto-joined to the workspace.

If you are an Admin but not the Owner, the **Admin** option does not appear in the invite role list or in the member role dropdowns, and an Admin member's role is shown as a read-only badge. A note under the form reads "Only the owner can grant or change the admin role."

The pending-invitations list shows expiry time. Each row supports:

- `Resend` — Invalidates the existing token immediately and emails a fresh one. The expiry clock restarts from the new send time.
- `Revoke` — Discards a pending invitation. Already-accepted invitations cannot be revoked.

> Re-inviting the same email auto-invalidates the existing token and issues a new one — there's never more than one live token per (workspace, email).

When you click the `Accept invitation` button in the email, one of three screens opens: sign-up, sign-in, or the invitation accept screen, depending on whether you're signed in and whether an account already exists.

- **Not signed up yet**: The email field is prefilled and locked (you cannot register under a different email — this is an intentional safeguard against permission escalation via leaked tokens). Just set a password and name, and on submit you're signed up, joined to the workspace, and routed to the dashboard. **No email-verification step** — the token itself proves ownership.
- **Has an account but is not signed in**: If an account already exists for the invited email, you're taken to the [sign-in](/login) screen instead of the sign-up screen. A brief notice reads "This email already has an account. Sign in to accept the invitation.", and the sign-in screen shows "Sign in to continue to the invitation."
- **Already signed in**: The invitation accept screen opens right away. If the signed-in account's email matches the invited email, click `Accept` to join. If you're signed in with a different account, a notice and a `Sign in with another account` button appear. The button signs you out and takes you to the sign-in screen, and once you sign in with the invited account you come back to the same invitation accept screen.
- **Expired / consumed token**: A banner explains what happened. Ask the workspace Admin to resend.

### Returning to the invitation after you sign in

If you sign in after arriving from an invitation link, you come back to the invitation accept screen. This is the same for password, two-factor authentication, and Google · GitHub sign-in. Signing in alone does not accept the invitation: click `Accept` on the screen you return to, and you join the workspace.

The `Sign in` link under the sign-up form also returns you to the invitation accept screen after you sign in, when you arrived from an invitation link.

<Callout type="note">
  An existing account whose email has not been verified cannot sign in. Handle the verification email first, then click the `Accept invitation` button in the invitation email again.
</Callout>

## Shared workflows (Team badge)

When you switch to a team workspace, every workflow in the list gets a `👥 Team` badge. The badge is a visual cue that "this workflow is visible and editable by other members of the same team." Personal workspaces don't show the badge.

### Ownership filter

In team workspaces, an additional `All / Mine / Shared` button group appears next to the search box. It lets you slice the list by author within the same team. The group is hidden in personal workspaces.

## Workspace settings

You can adjust default behavior from the **Settings** tab in workspace management.

### Default timezone

When you create a schedule without specifying a timezone, the workspace's **default timezone** is used. The value must be a valid IANA identifier (e.g. `Asia/Seoul`, `America/New_York`). If not set, `Asia/Seoul` is the default.

You can set it from the **Default timezone** card on the **Overview** tab of the settings screen. Editing requires Admin or above; all members can view. Clearing the field and saving removes the workspace default timezone.

Admins and above remove a member with the trash button on the member's row in **Workspace settings → Members**. Pressing it doesn't remove the member right away. A confirmation dialog opens first.

- The dialog is titled `Remove member` and asks "Remove Jane from the workspace?", with the member's own name in place of Jane.
- Below it you see "Personal integrations this member added to this workspace will also be deleted."
- `Remove` removes the member. `Cancel` changes nothing.

The dialog doesn't show whether the member has personal integrations or how many. The notice is the same sentence even if there are none. An Owner can't be removed. What happens to the personal integrations is described in the "Leaving or being removed also deletes personal integrations" section below.

## Leaving · deleting

  describes="Workspace settings → Danger zone tab: the Leave button and the leave confirmation dialog"

- **Leave** (Danger zone tab) — Removes your own membership and also deletes the personal integrations you added to this workspace. The confirmation dialog always shows "Personal integrations you added to this workspace will also be deleted." Blocked if you're the sole Owner — use [Transfer ownership] or [Delete workspace] first.
- **Transfer ownership** — Pick a non-Owner member to receive the role. Both members' roles swap atomically (target → Owner, you → Admin).
- **Delete workspace** — Owner-only. Re-enter the workspace name to confirm; members, invitations, and the workspace itself are removed in one transaction.

### Leaving or being removed also deletes personal integrations

When a member leaves the workspace, or an admin removes a member, every personal integration (Personal) that member added to this workspace is deleted along with the membership.

- **Status and usage don't matter.** Connected, pending install, expired, and error integrations are all deleted, even when a workflow node uses them. A regular integration delete is blocked while the integration is in use, but this one isn't.
- **Some integrations stay.** Organization integrations the member created, and other members' personal integrations, are kept.
- **It is recorded in the audit log.** Each deleted integration leaves an integration-deleted entry in the audit log.
- **Nodes fail at run time.** A workflow node that used a deleted personal integration fails to run until you pick another integration for it.
- **Sometimes nothing is deleted.** The sole Owner can't leave and an Owner can't be removed, so in those cases nothing is deleted.

<Callout type="warn">If the same person is invited again and rejoins, the deleted integrations do not come back. Create them again if you need them.</Callout>

See [Managing integrations](/docs/06-integrations-and-config/integration-management) for integration scope and permissions.

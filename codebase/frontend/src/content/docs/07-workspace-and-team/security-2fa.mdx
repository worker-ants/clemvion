[프로필 → 보안](/profile/security) 에서 **TOTP** (Authenticator 앱) 과 **Passkey · 보안 키** 두 가지 2단계 인증 방식을 모두 켜 둘 수 있어요. 각자 별도의 복구 코드 10개를 받고, 로그인 시 어떤 방식으로 통과할지는 정해진 우선순위를 따릅니다.

## 두 방식 비교

| 항목 | TOTP | Passkey · 보안 키 |
|------|------|-------------------|
| 호환 도구 | Google Authenticator · Authy · 1Password TOTP 등 | 기기 내장 Passkey (iPhone Face ID, Android, Windows Hello), YubiKey 같은 보안 키 |
| 등록 단계 | 계정 비밀번호 입력 → QR 코드 → 인증 앱 스캔 → 6자리 코드 입력 | 계정 비밀번호 입력 → 등록 버튼 → 브라우저 prompt → 기기 잠금 해제 / 지문 / PIN |
| 다중 등록 | 한 사용자당 1개 | **사용자당 N개** (모바일 + 데스크톱 + 보안 키 동시) |
| 복구 코드 | TOTP 활성화 시 10개 | 첫 Passkey 등록 시 10개 (**TOTP 와 별도 풀**) |
| Phishing 저항 | 약함 (코드가 노출 가능) | 강함 (origin 바인딩) |

> 두 방식 모두 활성화해 두는 걸 권장해요 — 휴대폰 분실·인증기 고장 시 다른 채널로 로그인할 수 있어요.

## TOTP 켜기

/>

TOTP 가 꺼져 있으면 [프로필 → 보안](/profile/security) 의 **2FA 설정** 카드에서 켤 수 있어요. 설정을 시작할 때 계정 비밀번호를 한 번 더 확인해요.

1. **계정 비밀번호** 를 입력해요. 8자 미만이면 "비밀번호를 입력해 주세요." 안내만 나오고 요청은 보내지 않아요.
2. **설정 시작** 을 눌러요. 비밀번호가 맞으면 QR 코드가 나타나요.
3. Authenticator 앱으로 QR 코드를 스캔해요.
4. 앱에 표시된 6자리 코드를 입력하고 **검증·활성화** 를 눌러요. 설정을 시작한 뒤 10분 안에 확인해야 해요.
5. 한 번만 표시되는 복구 코드 10개를 안전한 곳에 저장해요.

- 비밀번호가 맞지 않으면 "비밀번호가 맞지 않아요." 안내가 나오고 QR 코드를 받을 수 없어요.
- Google · GitHub 같은 소셜 로그인으로만 가입해 비밀번호가 없는 계정은 "비밀번호가 설정되지 않은 계정이에요. 비밀번호 재설정으로 먼저 설정해 주세요." 안내가 나오고 켤 수 없어요. [비밀번호 찾기](/forgot-password) 에서 비밀번호를 만든 뒤 다시 시도해요.
- 복구 코드는 카드가 켜진 상태로 바뀐 뒤에도 화면에 남아 있어요. TOTP 를 끄면 사라져요.
- 설정을 시작하고 10분이 지나면 "설정을 시작한 지 10분이 지났어요. 처음부터 다시 시작해 주세요." 안내가 나오고 QR 코드가 닫혀요. 비밀번호 입력 단계로 돌아가므로 비밀번호를 다시 넣고 새 QR 코드로 진행해요. 이전 QR 코드는 쓸 수 없어요.
- 아직 켜지 않았다면(검증 전) 화면을 새로 고쳐 설정을 처음부터 다시 시작할 수 있어요. 다시 시작하면 전에 받은 QR 코드는 쓸 수 없어요.
- 이미 켜진 계정에서는 설정 시작과 검증이 거부돼요. 다른 탭에서 먼저 켜 둔 경우에는 "2FA가 이미 활성화돼 있어요. 다시 설정하려면 먼저 비활성화해 주세요." 안내가 나오고 화면이 켜진 상태로 바뀌어요.

## TOTP 끄기

  kind="ui-entry"

  symbol="SecurityPage"
  describes="프로필 → 보안의 2FA 비활성 폼 (계정 비밀번호 + 인증 코드)"
/>

TOTP 가 켜져 있으면 [프로필 → 보안](/profile/security) 의 2FA 카드에 비활성 폼이 나타나요. 비밀번호만으로는 끌 수 없고, 입력란 두 개를 모두 채워야 해요.

1. **계정 비밀번호** 를 입력해요.
2. **6자리 코드 또는 복구 코드** 를 입력해요. Authenticator 앱에 표시된 6자리 코드를 넣거나, 앱을 쓸 수 없으면 TOTP 복구 코드 하나를 넣어요.
3. **2FA 비활성** 을 눌러요.

- 코드가 맞지 않으면 요청이 거부되고 2FA 는 켜진 채로 남아요.
- 복구 코드를 쓰면 로그인할 때처럼 그 코드는 사용 처리되어 다시 쓸 수 없어요.
- 끄고 나면 TOTP 비밀키와 남은 복구 코드가 모두 삭제돼요. 다시 켜면 새 복구 코드 10개를 받아요.
- Passkey 와 Passkey 복구 코드는 TOTP 와 별개라서 그대로 유지돼요.
- 요청이 너무 많으면 "요청이 너무 많아요. 잠시 뒤 다시 시도해 주세요." 안내가 나와요. 자동으로 다시 보내지 않으니 잠시 기다렸다가 직접 다시 눌러요. 한도는 아래 「요청 한도」에서 설명해요.

### Authenticator 앱이나 휴대폰을 바꿀 때

TOTP 가 켜진 동안에는 비밀키와 복구 코드를 바꿀 수 없어요. 이미 켜진 계정에서 설정을 다시 시작하거나 코드를 검증해 다시 활성화하는 요청은 거부돼요. 앱이나 휴대폰을 바꾸려면 TOTP 를 끈 다음 다시 켜요.

1. 위 순서로 TOTP 를 꺼요. 기존 앱을 쓸 수 없으면 TOTP 복구 코드로 꺼요.
2. 「TOTP 켜기」 순서대로 새 Authenticator 앱에 등록하고, 새로 표시되는 복구 코드 10개를 저장해요.

## Passkey 등록하기

1. [프로필 → 보안](/profile/security) 진입 → **Passkey · 보안 키** 카드에서 기기 이름(선택)과 **계정 비밀번호** 를 입력하고 **Passkey 등록** 클릭.
2. 브라우저가 인증기 선택 prompt 를 띄워요 — 기기 내장 Passkey, 보안 키, 다른 기기의 Passkey 중 고를 수 있어요.
3. 인증기 잠금 해제(지문 · Face ID · PIN) 가 끝나면 등록이 완료돼요.
4. **첫 Passkey 등록인 경우** 화면에 노란색 박스로 **WebAuthn 복구 코드 10개** 가 한 번만 표시돼요. 안전한 곳(비밀번호 매니저)에 저장해 주세요.

로그인 세션만 가로챈 사람이 자기 인증기를 등록해 원래 사용자가 로그인하지 못하게 만들 수 있어서 비밀번호를 다시 확인해요. 비밀번호는 인증기 창을 열기 전에 확인해요.

- 비밀번호가 8자보다 짧으면 요청하지 않고 "비밀번호를 입력해 주세요." 안내가 나와요.
- 비밀번호가 틀리면 "비밀번호가 맞지 않아요." 안내가 나와요.
- 소셜 로그인으로만 가입해 비밀번호가 없는 계정은 "비밀번호가 설정되지 않은 계정이에요. 비밀번호 재설정으로 먼저 설정해 주세요." 안내가 나와요. [비밀번호 찾기](/forgot-password) 에서 비밀번호를 만든 뒤 다시 시도해요.
- 세 경우 모두 인증기 창은 열리지 않아요.

> 이후 추가 등록 시에는 복구 코드가 다시 발급되지 않아요. 분실 시 카드 하단의 **복구 코드 재발급** 으로 새로 받을 수 있어요 (기존 미사용 코드는 폐기). 재발급 폼도 계정 비밀번호를 받고 위와 같은 안내를 써요.

### 브라우저 호환성

- 데스크톱: Chrome, Edge, Firefox, Safari 16+ 모두 지원.
- 모바일: iOS 16+ Safari, Android Chrome 모두 지원.
- 브라우저가 미지원이면 카드 상단에 경고가 표시되고 등록 버튼이 비활성화돼요. 이 경우 TOTP 만 사용하거나, 같은 계정으로 지원 브라우저에서 등록해 두면 다른 환경에서도 보안 키로 인증할 수 있어요.

## 로그인 시 무엇이 노출되나요?

[로그인](/login) 통과 후 2단계 인증 화면은 다음 우선순위를 따라요:

1. **Passkey 가 1개라도 등록되어 있으면** Passkey 인증 화면만 표시돼요. TOTP 입력란은 노출되지 않아요.
2. **Passkey 가 없고 TOTP 만 활성화** 되어 있으면 기존 TOTP 입력 화면이 표시돼요.
3. **둘 다 비활성** 이면 2FA 단계 자체를 건너뛰어요.

서버의 Passkey 기능이 꺼져 있으면(아래 「셀프 호스팅 환경 안내」 참고) 등록해 둔 Passkey 는 로그인에 쓰이지 않아요.

- TOTP 가 켜져 있으면 TOTP 입력 화면이 표시돼요.
- TOTP 가 꺼져 있으면 "지금은 Passkey 로 로그인할 수 없어요. 운영자에게 문의해 주세요." 안내가 나오고 로그인되지 않아요. 운영자가 Passkey 기능을 다시 켜면 로그인할 수 있어요.

> TOTP 로 우회해 로그인하고 싶다면 [프로필 → 보안](/profile/security) 에서 모든 Passkey 를 먼저 삭제해야 해요. 강한 인증 수단(Passkey) 이 등록된 상태에서 약한 수단(TOTP) 으로 자동 전환되는 것은 보안상 차단돼요.

### Passkey 인증이 실패하면?

- 화면 하단 **복구 코드 사용하기** 링크 → WebAuthn 전용 복구 코드 입력. 한 번 사용된 코드는 즉시 폐기돼요.
- 인증기를 분실한 경우, 같은 계정에 등록된 다른 Passkey(예: 보안 키) 로도 로그인할 수 있어요.
- 모든 Passkey + 복구 코드까지 분실하면 워크스페이스 관리자나 고객 지원이 계정 복구를 도와줘야 해요.

## Passkey 관리

- **이름 변경**: 목록의 연필 아이콘 → 새 이름 입력 → **저장**.
- **삭제**: 휴지통 아이콘 → 확인. 마지막 Passkey 를 삭제하면 WebAuthn 복구 코드도 함께 폐기돼요.
- **마지막 사용 시각** · **등록일** · **transports** (usb · nfc · ble · internal · hybrid) 가 각 행에 표시돼 의심스러운 인증기를 식별할 수 있어요.

## 요청 한도

다음 작업은 사용자당 1분에 10번까지 요청할 수 있어요.

- Passkey 등록
- Passkey 복구 코드 재발급
- TOTP 설정 시작
- TOTP 인증 코드 확인
- 2단계 인증 끄기

한도를 넘으면 "요청이 너무 많아요. 잠시 뒤 다시 시도해 주세요." 안내가 나와요. 화면이 자동으로 다시 보내지 않으니 잠시 기다린 뒤 직접 다시 시도해요.

## 셀프 호스팅 환경 안내

운영 도메인이 SaaS 와 다르면 다음 환경변수를 설정해 주세요:

| 변수 | 예 | 설명 |
|------|----|------|
| `WEBAUTHN_RP_ID` | `clemvion.example.com` | Relying Party ID. 호스트명만, 포트·스킴 없음 |
| `WEBAUTHN_RP_NAME` | `Clemvion` | 브라우저 인증 prompt 에 표시될 이름 |
| `WEBAUTHN_ORIGIN` | `https://app.example.com,https://www.example.com` | 콤마 구분 origin 목록 (같은 RP 의 multi-origin 허용) |

`WEBAUTHN_RP_ID` 와 `WEBAUTHN_ORIGIN` 중 하나라도 빠지면 백엔드가 경고 로그를 남기고 Passkey 기능을 끈 채로 시작해요. 이때 Passkey 등록과 Passkey 로그인은 거절되고, Passkey 만 등록하고 TOTP 를 끈 계정은 로그인할 수 없어요. 개발 · 시연 환경에서는 `WEBAUTHN_ALLOW_FALLBACK=1` 로 `FRONTEND_URL` 값을 대신 쓸 수 있지만 운영 환경에서는 두 변수를 직접 설정해 주세요. 잘못된 RP/origin 으로 등록한 Passkey 는 인증 시 항상 실패해요.

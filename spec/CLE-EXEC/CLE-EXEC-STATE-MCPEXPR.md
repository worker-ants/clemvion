## 개요

이 문서는 [실행 상태 머신과 대기·재개](CLE-EXEC-STATE.md) 의 하위 문서로 멀티턴 AI 에이전트의 재개 상태(`_resumeState` · `_resumeCheckpoint` · `_retryState`)에 싣는 MCP 서버의 표현식 여부를 정한다. 재개 상태 전반은 [입력 대기와 재개 상태](CLE-EXEC-STATE-RESUME.md#보존-예외-_resumecheckpoint) 에 있다. 이 값을 쓰는 개인 통합 판정은 [통합 노드 공통](../CLE-NODE-INT/CLE-NODE-INT-COMMON.md#integrationsservice-api-실행-엔진용) 이, 서버 항목의 필드 표는 [AI 노드 공통](../CLE-NODE-AI/CLE-NODE-AI-COMMON.md#mcp-서버-연결-ai-에이전트-전용) 의 McpServerRef 구조가 정한다.

## 표현식 여부 배열

AI 에이전트 노드 핸들러는 첫 턴에 MCP 서버 목록(`mcpServers`)의 항목마다 그 항목의 통합 참조가 평가 전 원본에서 표현식이었는지 정한다. 결과는 서버 항목 안이 아니라 목록과 길이가 같은 불리언 배열 `mcpServerFromExpression` 에 저장한다. i 번째 값이 i 번째 서버의 표현식 여부다. 첫 턴에 원본을 확인하지 못한 항목은 표현식(`true`)이다([통합 노드 공통](../CLE-NODE-INT/CLE-NODE-INT-COMMON.md#integrationsservice-api-실행-엔진용) 의 리터럴 판정).

- 핸들러는 서버 항목에서 `fromExpression` 키를 지운 목록을 저장한다. 그래서 사용자 설정에 같은 키가 있어도 저장된 목록에 남지 않는다.
- `_resumeState` · `_resumeCheckpoint` · `_retryState` 는 서버 목록과 이 배열을 함께 싣는다.
- 재개·재시도 턴은 저장된 배열을 쓰고 원본 설정의 위치로 다시 맞추지 않는다. 서버 목록이 통째로 없을 때는 아래 [서버 목록이 통째로 없는 AI 재개 체크포인트](#서버-목록이-통째로-없는-ai-재개-체크포인트) 가 예외다.
- 도구 프로바이더는 도구 목록 구성 문맥(`ProviderBuildCtx`)에 실린 이 배열만 읽고 서버 항목의 키는 읽지 않는다.
- 배열이 없거나 길이가 서버 목록과 다르면 모든 서버를 표현식으로 본다. 길이가 같으면 값이 `false` 인 서버만 리터럴로 본다. 이 판정은 단위 테스트로 지킨다(`mcp-server-ref-use.spec.ts`).

## 표현식 여부 배열이 없는 옛 AI 재개 체크포인트

이 규칙 전에 저장한 AI 재개 체크포인트와 `_retryState` 에는 `mcpServerFromExpression` 이 없고 서버 항목 안에 `fromExpression` 이 있을 수 있다. 서버 목록이 있고 배열이 없으면 `buildRetryReentryState` 가 항목의 값을 배열로 옮긴다. 항목 값이 `false` 인 위치만 `false` 이고 나머지(값이 없거나 객체가 아닌 항목 포함)는 `true` 다. 옮긴 뒤 항목에서 그 키를 지운다. 서버 항목의 `fromExpression` 을 읽는 곳은 이 변환 한 곳뿐이다.

값이 없는 항목은 이 변환 뒤에도 표현식이다. 2026-10-25 규칙([«값이 없으면 표현식이다»](#mcp-서버-항목에-표현식-여부를-저장하고-스키마-버전을-올리지-않는다-2026-10-25))과 같은 결과라서 그 규칙보다 먼저 저장한 체크포인트를 다루는 [통합 관리](../CLE-INT/CLE-INT-MANAGE.md#개인-통합의-역할-하한과-노드-사용-기준을-정한다-2026-10-24) 이행은 이 변환으로 바뀌지 않는다.

## 서버 목록이 통째로 없는 AI 재개 체크포인트

위의 두 규칙은 서버 목록이 있을 때의 규칙이다. AI 재개 체크포인트나 `_retryState` 에 `mcpServers` 키 자체가 없으면 `buildRetryReentryState` 가 현재 `node.config` 를 다시 평가한 목록으로 서버 목록을 다시 만들고 `mcpServerFromExpression` 도 첫 턴과 같은 방법으로 다시 정한다.

- 저장된 배열이 있어도 쓰지 않는다. 그 배열은 함께 저장된 목록과 짝이라 새 목록에 맞지 않는다.
- 현재 `node.config` 의 평가 전 원본과 평가한 목록을 같은 순서의 항목끼리 비교한다. 원본 값이 문자열이고 평가한 값과 같으면 `false`(리터럴), 아니면 `true` 다. 원본 목록이 배열이 아니거나 길이가 다르면 모든 항목이 `true` 다.
- 노드 설정에 사용자가 넣은 `fromExpression` 은 쓰지 않는다. 그래서 목록이 없는 AI 재개 체크포인트로 재개하면 지금 노드 설정에서 리터럴로 고른 서버는 리터럴로 판정되고 표현식 서버는 표현식으로 판정된다.
- 빈 배열은 목록이 있는 것으로 보고 그대로 쓴다.

## 스키마 버전

`mcpServerFromExpression` 은 값이 없을 때의 뜻이 정해진 필드라서 `CHECKPOINT_SCHEMA_VERSION` 을 올리지 않고 더한다. 버전 규칙은 [입력 대기와 재개 상태](CLE-EXEC-STATE-RESUME.md#보존-예외-_resumecheckpoint) 에 있다.

## 구현 위치

- `codebase/backend/src/nodes/ai/ai-agent/mcp-server-ref-use.ts` (`markMcpServerRefOrigins` · `liftLegacyMcpServerFromExpression` · `mcpServerRefUse`. MCP 서버의 표현식 여부 배열을 정하고, 옛 항목 값을 옮기고, 읽는다)
- `codebase/backend/src/modules/execution-engine/utils/resume-state.schema.ts` (서버 목록과 `mcpServerFromExpression` 을 함께 싣는다)

## Rationale

### MCP 서버 항목에 표현식 여부를 저장하고 스키마 버전을 올리지 않는다 (2026-10-25)

NERV Task `CLE-T-MG0EQZ` 에서 표현식으로 정한 통합 참조는 조직 통합만 쓰게 했다([통합 관리](../CLE-INT/CLE-INT-MANAGE.md) Rationale 「표현식으로 정한 통합 참조는 조직 통합만 쓴다」). 멀티턴 재개·재시도 턴은 실행 컨텍스트 없이 들어오므로 서버마다 표현식이었는지를 체크포인트에서 알아야 한다. 2026-11-07 에 저장 위치를 서버 항목 밖 배열로 옮겼다([표현식 여부를 서버 항목 밖 배열로 옮긴다](#표현식-여부를-서버-항목-밖-배열로-옮긴다-2026-11-07)). 아래의 «핸들러가 늘 덮어쓴다» 는 그 전 형식의 결정이다.

- **위치로 맞추지 않는다**: 재개 턴의 서버 목록은 첫 턴에 평가한 값인데 `rawConfig` 는 재개마다 현재 `node.config` 로 다시 만든다([실행 컨텍스트](CLE-EXEC-CONTEXT.md) 「멀티턴 설정은 턴마다 새로 만든다」). 위치로 다시 맞추면 정지 중에 서버를 재정렬하거나 지웠을 때 다른 서버의 값을 읽는다. 서버 항목의 키로 맞추는 안도 봤다. 항목에는 `integrationId` 말고 고유 키가 없고 표현식 항목은 원본에 그 ID 가 없어서 쓰지 않았다. 서버 목록이 통째로 없어 현재 `node.config` 에서 목록을 함께 다시 만드는 경우는 아래 «목록이 통째로 없으면 첫 턴처럼 다시 정한다» 가 예외다([서버 목록이 통째로 없는 AI 재개 체크포인트](#서버-목록이-통째로-없는-ai-재개-체크포인트)).
- **핸들러가 늘 덮어쓴다**: API 나 가져오기로 사용자 설정의 서버 항목에 `fromExpression: false` 가 들어와도 표현식 참조의 거절을 피하지 못하게 하려는 것이다.
- **값이 없으면 표현식이다**: 기본값을 리터럴로 두면 배포 전에 표현식으로 고른 개인 통합이 재개 턴에서 판정을 피한다. 대가로 배포 때 입력 대기 중이던 대화는 워크플로우 작성자 자신의 개인 통합 서버도 재개 턴에서 건너뛴다. 그 수를 세고 다루는 방법은 [통합 관리](../CLE-INT/CLE-INT-MANAGE.md#개인-통합의-역할-하한과-노드-사용-기준을-정한다-2026-10-24) 이행이 정한다.
- **목록이 통째로 없으면 첫 턴처럼 다시 정한다**: 이때 서버 목록은 AI 재개 체크포인트가 아니라 현재 `node.config` 에서 나온다. 그 목록의 `fromExpression` 을 노드 설정에 적힌 값 그대로 쓰면 사용자가 넣은 `fromExpression: false` 로 판정을 피할 수 있다. 그래서 첫 턴과 같이 평가 전 원본과 평가한 값을 비교해 다시 정한다. 목록이 함께 다시 만들어지므로 위치가 어긋날 일이 없다. 항목 하나에만 값이 없을 때는 그 항목을 원본과 다시 맞출 수 없어서 표현식으로 본다. 목록 전체가 없으면 현재 설정에서 목록을 다시 만들 수 있어서 그렇게 볼 이유가 없다. 모든 항목을 표현식으로 보는 안은 고르지 않았다. 그렇게 하면 지금 노드 설정에서 리터럴로 고른 서버까지 표현식으로 판정돼 워크플로우 작성자 자신의 개인 통합 서버도 재개 턴에서 거절된다.
- **스키마 버전을 올리지 않는다**: 버전을 올리면 롤링 배포 중 옛 인스턴스가 새 체크포인트를 미래 버전으로 보고 대화를 `RESUME_INCOMPATIBLE_STATE` 로 정리한다. 올리지 않아도 깨지는 쪽이 없다. 옛 인스턴스는 개인 통합 판정을 하지 않아 이 값을 읽지 않고 `resumeStateSchema` 는 `mcpServers` 항목의 모양을 보지 않는다. 새 인스턴스는 값이 없는 옛 항목을 위 규칙대로 표현식으로 본다.

### 표현식 여부를 서버 항목 밖 배열로 옮긴다 (2026-11-07)

NERV Task `CLE-T-68XG50`. 2026-10-25 결정은 표현식 여부를 서버 항목(`mcpServers[]`) 안의 `fromExpression` 에 실었다. 그 항목은 사용자 설정과 모양이 같다. 그래서 핸들러의 표식 함수를 거치지 않고 설정을 도구 목록 구성 문맥이나 상태에 싣는 경로가 새로 생기면 사용자가 넣은 `fromExpression: false` 를 그대로 믿는다. 지금은 그런 경로가 없지만 그것을 지키는 장치는 리뷰뿐이었다. 그래서 판정 근거를 설정 밖의 평행 배열 `mcpServerFromExpression` 으로 옮겼다. 표식을 거치지 않은 경로에는 배열이 없으므로 모든 서버가 표현식으로 판정되고 개인 통합이 열리지 않는다.

- **옛 체크포인트의 항목 값은 복원 한 곳에서 옮긴다**: 배포 때 입력 대기 중이던 대화도 첫 턴의 판정대로 이어진다. 항목 값을 읽는 코드는 `buildRetryReentryState` 의 변환 한 곳에만 남는다. 2026-10-29 뒤에 저장한 항목 값은 핸들러가 늘 덮어쓴 값이다. 그 전에 저장한 체크포인트 항목에는 노드 설정의 키가 그대로 실렸을 수 있다. 그때는 이 키에 뜻이 없어 넣을 이유가 없었고 변경 전 코드도 같은 값을 읽었으므로 이 변경으로 넓어지는 틈은 아니다.
- **배열은 함께 저장한 서버 목록과 짝이다**: 2026-10-25 에 [«위치로 맞추지 않는다»](#mcp-서버-항목에-표현식-여부를-저장하고-스키마-버전을-올리지-않는다-2026-10-25) 로 기각한 것은 저장된 서버 목록을 재개 때 다시 만든 현재 `node.config` 와 위치로 맞추는 안이다. 배열은 첫 턴에 서버 목록과 함께 만들고 같은 상태에 함께 저장한다. 그래서 정지 중에 노드 설정의 서버를 재정렬하거나 지워도 둘이 어긋나지 않는다. 첫 턴의 표식은 목록과 배열을 한 함수에서 함께 만들므로 길이가 다른 배열은 거기서 생기지 않는다. 길이가 다르면 짝이 깨진 것으로 보고 모든 서버를 표현식으로 본다(닫힌 쪽 실패). 대가로 그 행에서는 워크플로우 작성자 자신의 개인 통합 서버도 거절된다.
- **기각: 옛 항목 값을 버리고 모두 표현식으로 보는 안**: 항목 값을 읽는 코드가 하나도 남지 않는다. 대신 배포 때 입력 대기 중이던 대화는 워크플로우 작성자 자신의 개인 통합 서버도 재개 턴에서 거절된다.
- **기각: 형식은 그대로 두고 정적 가드와 회귀 테스트만 더하는 안**: `mcpServers` 속성에 값을 쓰는 지점을 허용 목록과 대조하는 가드다. 가드는 속성 쓰기만 보므로 평가한 설정을 통째로 넘기거나 펼쳐 섞는 경로는 잡지 못하고, 놓치면 인가가 열린다.
- **저장하는 목록에서 항목의 키를 지운다**: 롤링 배포 중 옛 인스턴스는 항목의 `fromExpression` 을 읽는다. 새 인스턴스가 사용자 키를 남긴 채 저장하면 옛 인스턴스가 그 값을 믿는다. 키를 지우면 옛 인스턴스는 모든 서버를 표현식으로 본다. 그 턴에서 리터럴로 고른 개인 통합 서버가 거절되지만 닫힌 쪽 실패이고 배포 중에만 생긴다.
- **스키마 버전을 올리지 않는다**: 2026-10-25 결정과 같은 이유다. 배열이 없을 때의 뜻(위 옮기기 규칙)이 정해져 있고 `resumeStateSchema` 는 런타임 검증에 쓰지 않는다.
- **배열 이름**: 개인 통합 판정 입력(`IntegrationUse.fromExpression`)과 같은 말을 쓰려고 `mcpServerFromExpression` 으로 정했다.

## 개요

이 문서는 Clemvion 의 제품명 표기, 브랜드 스토리와 핵심 개념, 시각 정체성(로고·색·타이포그래피), 어조를 정한다. 로고 변종과 색은 이 문서가 단일 기준이다. 사이드바·인증 화면 같은 개별 화면 문서는 로고가 어디에 놓이는지만 정하고, 어떤 변종과 색을 쓰는지는 이 문서를 따른다.

범위 밖: 제품 정의·목표·대상 사용자는 [Clemvion 제품 개요](../CLE-VISION.md) 가 정한다. 사이드바 로고 자리는 [레이아웃과 내비게이션](CLE-UI-LAYOUT.md), 인증 화면 카드는 [가입과 로그인](../CLE-ACCT/CLE-ACCT-SIGNIN.md) 이 정한다. 화면 문구의 문체 규칙은 [다국어와 화면 문구](CLE-UI-I18N.md) 에 있다.

## 제품명

**Clemvion**. 영문 표기 그대로 쓴다. 한글 표기나 다른 로마자 표기를 따로 두지 않고 한 이름을 공통으로 쓴다.

## 브랜드 스토리

Clemvion 은 작업·시스템·지능을 유연하게 하나로 엮어, 맥락이 공유되고 스스로 확장되는 실행 구조를 만든다.

기존 워크플로우는 사람이 설계하고 사람이 유지해야 했다. 그러나 실제 업무는 고정된 흐름이 아니라 끊임없이 변하고, 연결되고, 판단을 요구한다. Clemvion 은 이 간극에서 출발한다.

> "흐름은 설계하는 것이 아니라, 자라나야 한다."

### Clemvion 이란

AI 에이전트와 노코드 워크플로우 빌더를 합친 실행 플랫폼이다. 제품 정의는 [Clemvion 제품 개요](../CLE-VISION.md) 에 있다. 브랜드 메시지로는 다음을 강조한다. 워크플로우 안에 AI 에이전트 노드를 넣어 각 단계가 단순 실행이 아니라 판단과 적응을 한다. 사용자는 AI 어시스턴트와 대화하며 워크플로우를 만들고, 고치고, 디버깅할 수 있다.

### 핵심 개념

| # | 개념 | 정의 |
| --- | --- | --- |
| 1 | **Living Workflow** | 워크플로우는 더 이상 고정된 스크립트가 아니다. 실행되며 바뀌고, 상황에 맞게 스스로 이어진다 |
| 2 | **Agent-Native Nodes** | 각 노드는 단순 기능 블록이 아니라 지능을 가진 실행 단위다. 조건 분기·예외 처리·데이터 해석까지 에이전트가 직접 한다 |
| 3 | **Conversational Building** | 코드를 쓰지 않아도 된다. AI 와 대화하며 워크플로우를 설계하고, 문제가 생기면 함께 디버깅한다 |
| 4 | **Deep Integration** | 외부 서비스와 내부 시스템을 노드로 직접 잇는다. API·SaaS·사내 도구가 한 흐름 안에서 자연스럽게 동작한다 |

### Clemvion 이 필요한 곳

- 반복 작업 자동화를 넘어서고 싶은 팀
- 복잡한 시스템을 하나의 흐름으로 합치고 싶은 조직
- 사람이 아니라 시스템이 실행을 책임지길 원하는 환경

Clemvion 은 이런 요구를 단순한 도구가 아니라 스스로 동작하는 구조로 해결한다.

### 한 줄 정의

> Clemvion = AI 가 엮고, 실행하고, 성장시키는 워크플로우 시스템

### 브랜드 비전

우리는 도구를 만드는 것이 아니다. 일이 스스로 이루어지는 방식을 다시 정의한다.

Clemvion 은 사람이 모든 흐름을 통제하던 시대에서 지능이 흐름을 운영하는 시대로 옮겨 가는 전환을 만든다.

## 시각 정체성

### 디자인 모티프

Clemvion 마크는 원형 단위 두 개(위쪽의 큰 원형 노드와 왼쪽 아래의 보조 원형 노드)가 단일 path 안에서 유기적으로 이어진 추상 마크다. 두 노드 사이의 음각 공간은 연결 관계를, 바깥으로 흘러나가는 곡선은 흐름을 나타낸다.

- 위쪽 큰 원: Living Workflow 의 주된 실행 흐름
- 왼쪽 아래 작은 원: Agent-Native Nodes 의 판단 분기
- 두 원을 잇는 몸체: Conversational Building 의 연결 관계

자산은 단일 `<path>` 와 linear gradient 로 이루어진다. 이 모티프는 "흐름은 자라나야 한다" 는 브랜드 스토리를 시각으로 옮긴 것이고, 노드와 노드 사이의 관계를 추상화한다.

### 색 (보류)

정식 컬러 가이드는 나중에 도입한다. 지금은 두 가지만 정한다.

1. **자산 안에 박힌 색**: 로고와 파비콘 SVG 는 자체 fill 로 다음 값을 쓴다. 이 값은 SVG 안에 박혀 있고, 앱 테마 토큰으로 매핑하는 것은 이 문서의 책임 밖이다(지금은 매핑이 없다).
   - **마크 그라데이션**(라이트·다크 공용): linear-gradient `#12acaa`(teal) → `#8be67e`(lime). 그라데이션 좌표는 `userSpaceOnUse` 로 path 경계 상자의 대각선(`(69.856, 105.446)` → `(30.467, 58.503)`, mm 단위 원 path 좌표계)이다. 라이트·다크 모두 같은 stop 을 쓴다. 마크가 충분히 밝아 두 배경 모두에서 알아볼 수 있다.
   - **로고 자산 컨테이너 fill**: transparent. 라이트·다크 배경 위에 그대로 얹힌다.
   - **워드마크 fill**: 라이트 `#000000`(순수 검정), 다크 `#ffffff`(순수 흰색).
   - **유틸리티 자산 컨테이너 fill**(favicon-16·icon·apple-icon·OG): 브랜드 표상 자산이 아니라 브라우저 탭·iOS 홈 화면·소셜 카드용이다. 잘 보이도록 컨테이너 fill 을 둔다. favicon-16·icon·apple-icon 은 `#eef5ec`, OG 는 `#f7f8f6` 이다. transparent 규정은 브랜드 표상 자산(로고·마크·워드마크)에만 적용한다.
2. **앱 테마**: 지금 `codebase/frontend/src/app/globals.css` 는 Shadcn neutral 토큰을 쓴다(`--primary` 등이 라이트에서 거의 검정, 다크에서 거의 흰색). 브랜드 색을 앱 테마에 넣는 정식 결정은 이 절을 나중에 고칠 때 한다.

### 타이포그래피

| 쓰임 | 폰트 | 비고 |
| --- | --- | --- |
| 본문·UI | **Geist Sans** | `next/font/google` |
| 코드·모노 | **Geist Mono** | |
| 워드마크 | 시스템 sans-serif(`Helvetica Neue`, `Helvetica`, `Arial`) | weight **500**, letter-spacing `-1px`, font-size **48px**(풀로고·워드마크 전용 공통). 첫 글자 대문자 `C` + 나머지 소문자 `lemvion` → *Clemvion*. 흑백 단일 fill(라이트 `#000000`, 다크 `#ffffff`). SVG 자산에 박혀 있다 |

워드마크 SVG 가 `fontFamily` 에 시스템 폰트를 적는 이유는 Geist 가 없는 환경에서도 weight 500 이 안정적으로 보이게 하려는 것이다. 본문·UI 폰트는 Geist Sans 를 유지한다.

브랜드 태그라인 *Agentic Workflow* 는 풀로고 그림 안에 넣지 않는다. 풀로고 변종의 alt 텍스트와 메타데이터(OG `<meta>` description 등)에만 나온다.

#### 16px 파비콘

16×16 파비콘은 정식 마크의 단일 path 를 그대로 줄인다. 마크가 path 하나로 단순해 따로 단순화할 필요가 없다. 16px 에서도 마크 윤곽을 알아볼 수 있어야 하고, 알아보기 어려우면 별도 벡터 자산을 둔다.

#### 풀로고 구성

풀로고는 두 요소로 이루어진다.

1. Icon mark(왼쪽)
2. 워드마크 `Clemvion`(오른쪽, 대문자 C)

태그라인 *Agentic Workflow* 는 풀로고 SVG 그림에 넣지 않고 다음에만 남는다.

- `<img alt>`·`<svg aria-label>`: 풀로고 변종에만. 마크·워드마크 전용 변종의 alt 는 "Clemvion" 한 단어다.
- 마케팅 페이지의 히어로 문구, OG 메타 description, `<title>`: 이 문서의 책임 밖이고 각 화면 문서가 정한다.

풀로고 기본 viewBox 는 `320 × 80` 이다(Icon mark 60×60 + 왼쪽 여백 10 + 워드마크 영역 230 + 오른쪽 여백 20).

#### 워드마크 사용 규정

워드마크는 흑백 단일 fill 이다.

- 표기: 첫 글자 대문자 `C` + 나머지 소문자 `lemvion` → *Clemvion*
- 폰트: 위 타이포그래피 표의 시스템 sans-serif
- weight: 500(medium)
- font-size: 48(풀로고·워드마크 전용 공통)
- letter-spacing: -1
- fill: 라이트 배경 `#000000`, 다크 배경 `#ffffff`
- 배경: 자산 SVG 컨테이너 fill 없음(transparent). 라이트·다크 배경 위에 그대로 얹힌다

금지: 워드마크 자체의 그라데이션 fill, 외곽선, 그림자, 회전, 왜곡, 임의 색 바꾸기. 워드마크가 놓이는 페이지 배경의 그라데이션 여부는 이 문서가 정하지 않고 각 화면 문서의 자리 정의를 따른다.

#### 여백과 최소 크기

| 항목 | 규정 |
| --- | --- |
| 여백(clear space) | 워드마크 `clemvion` 의 x-height 만큼. 풀로고의 모든 바깥쪽에 적용한다 |
| 최소 풀로고 너비 | **160px**. 이보다 작으면 Icon mark 만이나 워드마크만으로 바꾼다 |
| 최소 Icon mark 한 변 | **16px**. 이보다 작게 쓰지 않는다 |
| 풀로고·워드마크 배치 | 가로 배치 고정. 세로로 쌓은 변종은 다루지 않는다 |

#### 로고 노출 자리

이 문서는 다음 자리의 로고 노출을 정식 사양으로 둔다. 이 절은 개별 화면 문서의 로고 서술보다 우선한다. 화면 문서는 노출 위치만 정하고, 변종과 색은 이 절을 따른다.

| 자리 | 변종 | 비고 |
| --- | --- | --- |
| 사이드바 상단([레이아웃과 내비게이션](CLE-UI-LAYOUT.md)) | 펼침 → Full logo(`theme="auto"`), 접힘 → Icon mark(`theme="auto"`) | 누르면 `/dashboard`. 사이드바 헤더 줄은 전용 어두운 배경 없이 사이드바 표면(`--card`) 그대로다 |
| 인증 화면(`/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email`) | Full logo(`theme="auto"`) | 인증 카드 위 가운데. 로고 감싸개는 전용 어두운 배경 없이 인증 그라데이션 표면 위에 투명하게 얹힌다. 카드의 배경과 여백은 [가입과 로그인](../CLE-ACCT/CLE-ACCT-SIGNIN.md) 이 정한다 |
| 브라우저 탭 | Favicon multi | 라이트·다크 자동 전환은 브라우저 표준 동작에 맡긴다 |
| iOS 홈 화면 | Apple touch icon | 180×180(지금은 임시 SVG, PNG 는 후속 작업) |
| SNS·외부 공유 | OG image | 1200×630(지금은 임시 SVG, 메타데이터 비활성, 후속 작업) |

라이트·다크 자산은 노출 자리의 배경 톤을 기준으로 고른다. 사이드바와 인증 화면 모두 전용 어두운 배경 없이 표면(Shadcn `--card`, 인증 그라데이션) 위에 투명 로고를 얹는다. `<Logo theme="auto">` 가 현재 테마를 따라 라이트·다크 자산을 자동으로 바꾼다.

### 어조와 스타일

- 한국어를 1차 언어로 쓴다. 영어 표기는 제품명과 고유명사에 한정한다.
- 핵심 마케팅 문구에는 의인화와 자연 비유(자라다, 뻗다, 엮다, 흐름)를 쓴다.
- 기능 설명에는 과장이나 감탄사 없이 짧고 단정한 문장을 쓴다.

### 임시 자산 상태

다음 셋은 후속 작업 대상이다. PNG 는 지금 SVG 자산에서 만든다.

- `apple-icon.png`(180×180 PNG): iOS 12 이상은 SVG apple-touch-icon 을 지원해 지금은 임시 SVG 로 노출한다. 래스터 도구(sharp·ImageMagick)를 들인 뒤 PNG 로 바꾸고 메타데이터를 고친다.
- `opengraph-image.png`(1200×630 PNG): SVG OG 카드는 X·Slack·Facebook 크롤러 호환성이 불안정해 `codebase/frontend/src/app/layout.tsx` 의 `openGraph.images`·`twitter.images` 를 꺼 두었다. PNG 를 만든 뒤 `summary_large_image` 카드와 `images: [{ url: "/opengraph-image.png", width: 1200, height: 630 }]` 를 다시 켠다.
- `favicon.ico` 합성본(16/32/48): 요즘 브라우저는 `icon.svg` 를 먼저 쓰므로 지금은 영향이 없다. 래스터 도구를 들인 뒤 합성 `.ico` 를 만든다.

## Rationale

### 추상 단일 path 마크와 teal → lime 그라데이션

- 마크는 단일 `<path>` 와 linear gradient(`#12acaa` teal → `#8be67e` lime)로, 노드 자체의 조립이 아니라 노드 사이의 연결 관계를 추상화한다. Living Workflow 와 Agent-Native Nodes 라는 정체성을 단순한 형태로 전한다.
- 단일 path 는 16px 파비콘까지 따로 단순화하지 않고 그대로 줄일 수 있다.
- 식물·덩굴 곡선 모티프는 쓰지 않는다. 마크는 식물이 아니라 노드 사이 관계의 추상화다.
- 그라데이션은 라이트·다크 배경 모두에서 같은 stop 으로 알아볼 수 있어 배경별 색 단계가 따로 필요 없다.

### 워드마크: 흑백 단일, 대문자 C, 시스템 폰트

- `Clemvion`(첫 글자 대문자) 표기는 정식 제품명과 같다.
- weight 500 과 size 48 은 마크와 비슷한 시각 무게를 줘 균형 잡힌 조합을 만든다.
- fill 은 흑백 단일(라이트 `#000000`, 다크 `#ffffff`)이다. 배경 톤과의 대비라는 디자인 의도가 자산 안의 hex 와 1:1 로 맞는다. 강조색은 두지 않는다.
- `fontFamily` 에 시스템 sans-serif(`Helvetica Neue`, `Helvetica`, `Arial`)를 적는 이유는 Geist 가 없는 환경에서 weight 500 이 안정적으로 보이게 하려는 것이다. 본문·UI 폰트는 Geist Sans 를 유지한다.
- 풀로고는 마크와 워드마크 두 요소다. 태그라인 *Agentic Workflow* 는 풀로고 그림이 아니라 alt·aria-label·메타 description 에만 둔다. 풀로고 그림 영역을 줄여 좁은 헤더와 작은 카드에서 쓰기 쉽게 한다.

### 컨테이너 fill 을 투명으로 둔 이유

- 브랜드 표상 자산(로고·마크·워드마크)의 SVG 컨테이너 fill 은 transparent 다. 배경 톤은 자산을 쓰는 화면이 정한다. 자산은 벡터만 그린다.
- 유틸리티 자산(favicon-16·icon·apple-icon·opengraph-image)은 예외로 컨테이너 fill 을 둔다. 브라우저 탭·iOS 홈 화면·외부 소셜 카드는 배경 톤을 자산이 통제할 수 없어, 투명이면 잘 보이지 않고 일관성이 깨진다.

### 로고 자리에 `theme="auto"` 를 쓰고 전용 어두운 배경을 두지 않는 이유

- 사이드바 헤더와 인증 화면의 로고 감싸개에는 전용 어두운 배경을 두지 않는다. 투명 자산과 흑백 워드마크는 라이트 배경에서도 충분히 잘 보인다.
- `<Logo theme="auto">` 가 현재 테마를 따라 라이트·다크 자산을 자동으로 바꾼다. 마케팅 페이지·대시보드 카드 같은 다른 자리와 같은 방식으로 일관성을 지킨다.
- 인프라 설정: Tailwind v4 의 `dark:` variant 가 OS 의 `prefers-color-scheme` 대신 `.dark` 조상 클래스를 따르도록 `globals.css` 에 `@custom-variant dark (&:where(.dark, .dark *));` 를 둔다. 로고와 테마 전환은 OS 설정이 아니라 앱의 실제 테마 상태만 따른다.

### 브랜드 문서가 화면 문서보다 우선하는 이유

- 로고 노출 자리 절이 개별 화면 문서의 로고 서술보다 우선한다.
- 브랜드 자산의 변종과 색은 단일 기준 원칙에 따라 한 곳(이 문서)에서만 정한다. 화면 문서는 "로고가 어디에 놓이는가" 만 정하고 변종과 색은 이 문서를 따른다.

### 앱 테마 색 토큰화를 보류한 이유

- 마크 그라데이션(teal → lime)을 앱 테마 토큰에 매핑하는 일은 보류했다. `globals.css` 는 Shadcn neutral 팔레트를 쓴다.
- 정식 컬러 가이드는 사용자·디자이너와 함께 확정한 뒤, 이 문서의 색 절을 고치고 코드에 매핑한다.

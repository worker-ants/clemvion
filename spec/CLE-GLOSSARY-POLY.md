## 개요

[용어 사전](CLE-GLOSSARY.md) 의 「다의어 구분」이다. 여러 영역에서 같은 말이 다른 뜻으로 쓰이는 경우의 구분 표기다. 영역별 용어 문서의 표준 용어와 함께 쓴다.

## 다의어 구분

한 단어가 여러 뜻으로 쓰이는 경우다. 본문에서는 "구분 표기" 열의 말을 쓴다. 단어 자체를 단독으로 쓰지 않는다.

| 단어 | 뜻 | 구분 표기 |

| 실행 | 워크플로우가 한 번 도는 단위(`Execution`)(예: 실행이 입력 대기로 바뀐다) | 실행 |
| 실행 | 노드가 한 번 도는 단위(`NodeExecution`)(예: 반복 회차마다 노드 실행 행이 생긴다) | 노드 실행 |
| 실행 | 에디터 실행 버튼 동작(예: 사용자가 단일 노드 실행을 누른다) | 전체 실행, 단일 노드 실행, 선택 노드부터 실행 |
| 실행 | AI 어시스턴트의 셋째 단계(Execute)(예: 편집 단계에서 캔버스를 바꾼다) | 편집 단계 |

| 재실행 | 순환 연결선으로 같은 노드를 다시 방문(예: 되돌아가는 연결선이 노드 재방문을 만든다) | 노드 재방문 |
| 재개 | 사용자 입력으로 입력 대기 실행을 잇기(예: 폼 제출이 실행을 재개한다) | 재개 |

## Rationale

이 표는 영역별로 쪼개지 않았다. 여러 영역에 걸친 같은 말을 한 표에서 가르는 것이 이 표의 목적이다. 영역 문서로 나누면 그 비교가 사라진다.

2026-10-02 에 [용어 사전](CLE-GLOSSARY.md) 한 문서의 「다의어 구분」 절에서 옮겼다. 나눈 이유와 표준을 고른 기준은 그 문서의 Rationale 에 있다.

### 미러 반영 리뷰 뒤 고친 행 (2026-10-04)

- 「마스킹」 · 「임계」 행의 뜻 칸에 남아 있던 수치(보이는 글자 수, 알림 시점)를 뺐다(색인 표기 원칙 14). 보이는 글자 수는 [외부 호출 인증 설정](CLE-TRIG/CLE-TRIG-AUTHCFG.md) · [LLM 클라이언트](CLE-AI/CLE-AI-LLM.md) · [LLM 사용량 기록](CLE-AI/CLE-AI-USAGE.md), 알림 시점은 [통합 상태와 만료 알림](CLE-INT/CLE-INT-STATUS.md) · [알림](CLE-OBS/CLE-OBS-NOTIFY.md) 에 있다. 「알림」 의 외부 모니터링 행에 있는 PromQL 예 `[5m]` 은 코드 식의 일부라 둔다.

### 정의 보정 (2026-10-03)

NERV Task `CLE-T-V22XN8` 가 정한 정의 보정을 반영했다.

- 「예」 열을 지웠다. 264행 중 220행이 「없음」 이었다. 예가 있던 44행 가운데 43행은 그 예를 「뜻」 칸 괄호로 옮겼다. 예에 든 수치(횟수 · 주기 · 기간)는 옮기면서 뺐다(색인 표기 원칙 14). 「display-only」 행의 도구 개수도 지웠다. 「리뷰 라운드」 행의 예(같은 커밋을 다시 제출하면 같은 라운드에 합쳐진다)는 API 문서 행의 정의로 옮겼다.
- 단어 칸 표기를 통일했다. 한국어 단어에 영문을 붙일 때는 「한국어(영문)」, 여러 형태를 묶을 때는 「 · 」 로 쓴다(「recall·회수」 · 「stuck 회수」 → 「회수(recall · reclaim)」. 두 묶음에 같은 구분 표기 「처리 중 문서 회수」 가 겹쳐 있어 한 행으로 합쳤다. 결정 항목 D57(「회수」 의 두 뜻) 참조).
- 「세션」 의 리뷰 라운드 행은 정의를 되풀이하지 않고 [용어 사전 — API 와 개발 규약](CLE-GLOSSARY-API.md) 의 「리뷰 라운드」 를 가리킨다.
- 쓰지 않는 표기와 겹치던 말을 고쳤다. 「운영 콘솔 안 위젯 시연」 → 「웹채팅 운영 콘솔 안 위젯 시연」. 「실행 기록 재사용 정책」 은 결정 항목 D01(실행 내역 표기)이 정해진 뒤 고친다.
- 코드 식별자에 백틱을 붙였다(`refresh_token`, `interactionType`, 단어 칸의 `/docs` · `error` · `resumed`). 예가 아니라 규칙 문장이던 다섯 행은 「(예: …)」 대신 뜻 칸의 문장으로 옮겼다. 「지식 저장소」 의 「스펙·계획 문서 모음」 에서 지운 계획 문서를 뺐다. 구분 표기 「병합」 · 「호출」 에 한정어를 붙였다(브랜치 병합, 인증 설정 호출).

### 전환 단계 5 뒤 고친 행 (2026-10-03)

전환 단계 5 에서 옛 스펙 트리를 지운 뒤 맞췄다(NERV Task `CLE-T-RGZBCQ`).

- 「상태(status)」 의 옛 스펙 상태 행: "동결된 옛 스펙 트리" 를 현재형으로 적었다. 걷은 값으로 고쳤다.
- 「래칫(ratchet)」 두 행: [스펙과 구현 근거 규약](CLE-ENG/CLE-ENG-SPECEVIDENCE.md) 의 Rationale 「codebase 의 옛 경로는 래칫으로 막고 고칠 때 바꾼다」 와 [DB 마이그레이션 규약](CLE-ENG/CLE-ENG-MIGRATION.md) 이 문서마다 래칫을 따로 정의했다. 형제 가드 `hardcoded-korean-ratchet` 은 판정이 반대였다. 판정 방향이 뜻을 가르므로 구분 표기를 양방향 · 단방향으로 정했다. 저장소 테스트 주석에도 「양방향 래칫」 이라는 표현이 이미 있다(`user-entity-exposure.spec.ts`).

### 분할 검토에서 고친 행 (2026-10-02)

분할할 때와 분할한 초안의 일관성 검토에서 고친 행이다.

- 「세션」 의 리뷰 용어 두 행: 「리뷰 세션」 을 로컬 `.review/**` 디렉터리로 좁히고 「리뷰 라운드」 행을 더했다. 이유는 [용어 사전](CLE-GLOSSARY.md) 의 Rationale 「리뷰 용어를 NERV 레코드 기준으로 고친 이유」 에 있다.
- 「리뷰 세션」 뜻에 옛 `review/**` 디렉터리도 같은 이름이었음을 적었다. [리뷰 산출물 인용 규약](CLE-ENG/CLE-ENG-REVIEWCITE.md) 이 옛 인용 대상을 그 이름으로 부르기 때문이다.
- 「회수」 의 유휴 실행 행은 쓰지 않는 표기 「공개 위젯」 을 「웹채팅 위젯」 으로 바꿨다.
- 「상태(status)」 의 스펙 상태 행은 NERV 이전 뒤 갈린 문서 상태 · 구현 상태 · 옛 스펙 상태 세 행으로 나눴다.

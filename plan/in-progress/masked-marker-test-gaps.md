## 재판정 — 둘의 운명이 갈렸다

두 항목 다 트래커에 **유예 조건**이 붙어 있었다. 조건을 그대로 믿지 않고 실측했다.

### ① `throwIfAny` phase 경계 트레이드오프 — **집행한다** (갭 실재)

docstring 이 트레이드오프를 명시한다: ①(raw) 를 통과한 뒤 **무관한 필드의 진짜
`coerce_failed`** 가 resolve 를 선점하면 ②(JSON 문자열 안의 마커)가 **그 요청에서 실행되지
않는다.**

**기존 캐너리는 반대 방향만 덮는다** (실측): `[캐너리] raw 에서 걸리면 coerce_failed 가
섞이지 않는다` 는 **①이 걸리는** 경우다. ①이 **안 걸리고** ②가 건너뛰어지는 방향은
18개 테스트 어디에도 없다.

> **왜 고정할 가치가 있나**: 이 동작은 **의도된 설계**다(합치면 `coerce_failed` 가 섞여
> 안내가 흐려진다 — 이 시리즈가 되돌린 그 문제). 그런데 문서에만 있으면, 다음 사람이
> *"두 phase 를 합쳐 한 번에 다 보고하면 더 친절하지 않나"* 로 **선의로 되돌릴 수 있다.**
> 테스트가 없으면 그 되돌림이 조용히 통과한다.

### ② `findMaskedResubmissions` 직접 단위 테스트 — **유예 유지, 근거는 교체**

트래커의 유예 조건은 *"세 번째 소비처가 생기면 그때"* 였다. 실측: 소비처는 여전히
**함수 1개**(`resolveTriggerParametersRejectingMasked`)·호출 2곳(phase ①·②)이라 조건
미충족이다. **그러나 "N개가 되면" 은 그 자체로 검증 가능한 주장**이므로 개수가 아니라
**실제 커버리지**로 다시 판정했다.

| `findMaskedResubmissions` 의 분기 | 상위 함수 경유로 덮이나 |
| --- | --- |
| 빈/없는 스키마 → `[]` | ✅ `스키마가 없거나 비면 통과한다` |
| 비객체 `rawSource`/`values` → `[]` | ✅ `null·비객체 raw 를 안전하게 지나간다` |
| **`rawSource` 에 있는 키만** 대상 | ✅ `[캐너리] defaultValue 가 마커여도 손대지 않은 필드는 막지 않는다` |
| 정확 일치 경계 | ✅ `[캐너리] 마커를 포함만 하는 값은 통과` |
| 깊이 상한 · 배열/객체/혼합 보폭 | ✅ `[경계]` 4종 |
| 다중 필드 수집 | ✅ `여러 필드가 걸리면 전부 돌려준다` |

**모든 분기가 이미 덮여 있다.** 직접 단위 테스트를 지금 추가하면 같은 단언을 한 겹 얕은
곳에서 반복할 뿐이다.

> 유예는 유지하되 **근거를 교체**한다 — *"소비처가 3개 미만이라"* 가 아니라 *"분기 전수가
> 상위 경유로 이미 덮여 있어 추가분이 중복이라"* 다. 결론이 같아도 근거가 바뀐 것은 기록할
> 가치가 있다(다음 사람이 "3번째 소비처" 만 세고 지나치지 않도록).

## 등재 항목의 전제 두 개를 실측이 뒤집었다

### ① "§10 의 나머지 소절은 이미 전면 위임 구조" — **거짓**

등재할 때 처방 (b)("§10.4 를 위임만 남기고 메커니즘 서술을 삭제")의 근거로 그렇게 적었다.
§10 전문을 열어 보니 아니다:

| 소절 | 실제 |
|---|---|
| §10.1 연결 | 엔드포인트 URL **인라인** |
| §10.2 메시지 형식 | JSON 프레임 예시 **인라인** |
| §10.3 용도 | 용도 표 **인라인** (실행 제어 행만 §4.2 링크) |
| §10.4 재연결 | 불릿 2 + 註 2 |
| (§10 말미) | *"상세 프로토콜: … 참조"* — **위임은 여기 한 줄뿐** |

즉 §10 은 "짧은 인라인 요약 + 말미 위임" 구조다. §10.4 만 서술을 비우면 **그 소절이 §10 안에서
혼자 빈다.** 그러므로 **(a) 를 택한다** — 서술은 유지하되 사실을 맞추고 SoT 를 인용한다.

### ② 세 곳이 틀렸다 — 그중 **하나만** 내가 새로 찾았다

처음 이 절을 *"등재 항목은 두 번째 불릿만 지적했다"* 로 열었다. **틀렸다** (`plan_coherence`
WARNING). 트래커 원문은 두 번째 불릿과 **blockquote 의 구분 축을 둘 다** 지적하고
*"불릿만 고치면 註가 다시 모순을 만든다"* 는 처방까지 달았다. 실측으로 새로 추가되는 것은
**①(백오프 수치)** 한 곳이다. 게다가 이 초안은 두 문단 뒤에서 *"등재 항목이 이미 경고한
그대로다"* 라고 스스로 인정하고 있었다 — **자기 문서 안에서 모순됐다.**

정정하자면: 고칠 곳은 세 곳이고, 그중 트래커가 이미 아는 것이 둘, 내가 더한 것이 하나다.

```markdown
### 10.4 재연결

- 연결 끊김 시 지수 백오프로 재연결 (1s, 2s, 4s, ... 최대 30s)          ← ①
- 재연결 시 마지막 수신 이벤트 ID 전달 → 놓친 이벤트 재전송              ← ②

> **예외 — 서버가 끊은 경우:** 위 두 줄은 **전송 계층이 끊긴 경우**를 말한다. …     ← ③
> 복구 방식도 다르다 — … 놓친 이벤트는 스냅샷으로 복구한다.
```

### 그런데 세 곳의 **출처가 같지 않다** — 이게 이 항목의 핵심이다

`rationale_continuity` 가 `git log -S` 로 갈랐고, 나도 재확인했다.

|---|---|---|---|
| 불릿 2개 | `05089d5a6` | 2026-03-26 | 최초 초안 이후 **미수정** — 순수 legacy drift |
| WS §6.2 의 「native WS 버퍼 전제 폐기」 Rationale | `698bf30e2` | **2026-05-31** | *"폐기된 대안: native WS lastSeq 버퍼-replay 전면 구현"* 로 **명문 기각** |
| §10.4 예외 blockquote + `2-api-convention.md` Rationale 항목 | `7e6a4bc3e` (#1267) | **2026-09-02** | 폐기 선언 **3개월 뒤**, 그것을 인용하지 않은 채 내려진 **능동적 판단** |

**그래서 blockquote 는 "잊힌 잔재" 가 아니다.** 폐기 선언이 이미 spec 안에 3개월간 존재하는
상태에서, 그 선언을 대조하지 않고 *"전송 계층이 끊긴 경우에는 위 두 줄이 맞다"* 는 부분집합을
남겼다 — **폐기된 설계의 조건부 재도입**이다. 같은 날 커밋 메시지가 `#1265`·`#1266` 은
인용하면서 5월 폐기 항목은 한 번도 인용하지 않는다.

이걸 구분해 적는 이유는 처방이 같아도 **다음 사람에게 남는 교훈이 다르기** 때문이다. drift 의
교훈은 "요약을 주기적으로 SoT 와 대조하라" 이고, 이쪽의 교훈은 **"예외를 만들기 전에 그 주제의
Rationale 에 폐기 선언이 있는지 먼저 보라"** 다.

**① 백오프 수치가 SoT 가 스스로 부인한 값이다.** `6-websocket-protocol.md §6.1` 은 실제 동작을
Socket.IO Manager 내장으로 규정하고, 표의 지터 행이 *"spec 초안의 '±500ms' 수치는 Socket.IO 의
비율 기반 지터로 대체"* 라 적으며, 註가 못박는다 — *"구체 backoff sequence (1/2/4/8/16s) 는
**spec 초안 값**이며 실제는 Socket.IO Manager 의 내장 알고리즘을 따른다."* §10.4 의
`(1s, 2s, 4s, ... 최대 30s)` 가 바로 그 초안 시퀀스다. 즉 **SoT 가 "이건 초안 값" 이라고 적어
둔 숫자를 요약 문서가 사실로 옮겨 적고 있다.**

> **`cross_spec` 이 이걸 리터럴 일치까지 확증했다.** `git log -p -S "1/2/4/8/16s"` 로 보면
> 2026-06-03 audit 커밋(`cfffc1355`) **이전** §6.1 표의 "백오프 전략" 셀이 정확히
> *"지수 백오프 (1s, 2s, 4s, 8s, 16s, 최대 30s)"* 였다. §10.4 의 값은 그 문장에서 가운데
> (8s, 16s)만 `...` 로 줄인 **동일 시퀀스**다 — 근사값이 아니라 옛 값 그대로다.
>
> 그리고 **그 수치를 요약 문서에 의도적으로 남기기로 한 기록된 결정은 없다** —
> `2-api-convention.md`·`6-websocket-protocol.md`·`spec/conventions/**` 전체에서 "근사값"·
> "요약 문서는" 류 문구 **0건**(`rationale_continuity` 실측). 부재를 확인한 뒤 지운다.

**② native WS 에 last-event-ID 재전송이 없다.** `§6.2` 는 소제목부터
「native WebSocket 복구 모델 — `execution.snapshot`」이고, `seq` 기반 정밀 재전송은
**EIA SSE 어댑터 소유**다(§4.7 「5분 버퍼는 SSE 어댑터 소유」 ·
`14-external-interaction-api.md` §R7 이 seq 공유를 **SSE 와 notification 사이로 한정**).
게다가 이 문장은 §6.2 Rationale 이 *"WS 가 버퍼를 갖는다는 **폐기된 전제**"* 로 **철회**한
바로 그 주장이다.

**③ 註가 구분 축을 잘못 잡았다 — 이게 제일 고약하다.** 註는 두 경우를 **복구 방식**으로
가른다("전송 계층 끊김 = 위 두 줄 / 서버 disconnect = 스냅샷"). 실제로는 **복구 방식은 두 경우가
같다**(둘 다 재구독 시 snapshot). 다른 것은 **재연결이 자동으로 발화하는가**다 —
`§6.1` 예외: 서버가 `disconnect()` 하면 클라이언트는 reason `"io server disconnect"` 를 받고
Socket.IO 는 **재연결을 시도하지 않아** 클라이언트가 명시적으로 `socket.connect()` 를 불러야
한다(토큰 만료 종료 §1.2 가 그 경로).

즉 註는 **틀린 불릿을 "전송 계층 끊김에는 참" 으로 살려 두는 방식으로 봉인**하고 있다.
불릿만 고치면 註가 다시 모순을 만든다 — 등재 항목이 이미 경고한 그대로다.

## 변경안

### E-1. §10.4 전체 교체

```markdown
### 10.4 재연결

- **자동 재연결은 Socket.IO 클라이언트 내장**이다 — 지수 백오프 + 지터로 무제한 재시도한다.
  구체 파라미터는 구현이 SoT 이므로 여기 숫자를 두지 않는다
  ([WebSocket 프로토콜 §6.1](./6-websocket-protocol.md#61-클라이언트-재연결-socketio-내장)).
- **놓친 이벤트는 재구독 시 1회성 `execution.snapshot` 으로 재동기화한다**
  ([§6.2](./6-websocket-protocol.md#62-놓친-이벤트-복구)). native WS 에는 `seq` 기반 replay
  버퍼가 **없다** — 그 버퍼는 외부 EIA 의 SSE 어댑터가 소유하며 `Last-Event-Id` 로 제공한다
  ([§4.7](./6-websocket-protocol.md#47-외부-표면-매핑-external-interaction-api)). 두 전송은
  같은 `seq` 공간만 공유하고 버퍼는 공유하지 않는다.

> **자동 재연결이 안 되는 경우:** 서버가 스스로 `disconnect()` 하면(토큰 만료 종료)
> Socket.IO 는 재연결을 **시도하지 않는다** — 클라이언트가 명시적으로 재연결해야 한다.
> 갈리는 것은 **재연결 발화**이고 **복구 방식은 두 경우가 같다**(위 snapshot). 상세와 근거는
> [WebSocket 프로토콜 §1.2·§6.1·§6.2·§9.2](./6-websocket-protocol.md) 가 소유한다.

> **상세 프로토콜:** 채널 구독, 인증, heartbeat, 메시지 스키마 등은
> [WebSocket 프로토콜 상세](./6-websocket-protocol.md) 참조.
```

**바뀐 것**: ① 숫자를 지우고 §6.1 을 앵커로 인용(SoT 가 부인한 값을 옮겨 적지 않는다) ·
② snapshot 모델 + 버퍼 소유자 명시 · ③ 註의 구분 축을 "복구 방식" → **"재연결 발화"** 로 교정.

**유지한 것**: §10 의 인라인 요약 구조, 말미 위임 註, 그리고 註가 이미 걸어 둔
`§1.2·§6.1·§6.2·§9.2` 포인터.

### E-2 (신설) — 같은 문서 `## Rationale` 의 2026-09-02 항목을 갱신한다

**세 checker 가 독립적으로 같은 갭을 짚었다** (`cross_spec` WARNING · `rationale_continuity`
WARNING · `convention_compliance` WARNING). `2-api-convention.md` 는 §10.4 를 대상으로 한
Rationale 항목을 **자기 안에** 갖고 있고(「§10.4 재연결 요약에 예외를 "복제" 하지 않고 "위임" 한
이유」, 2026-09-02), 그 첫 문장이 정확히 내가 ③에서 지적한 **틀린 축**에 서 있다:

> §10.4 는 재연결을 두 줄로 요약하는데, 그 둘 다 **서버가 스스로 끊은 경우**에는 틀리다 —
> … 복구도 마지막 이벤트 ID 재전송이 아니라 스냅샷이다.

*"서버가 끊은 경우에는 틀리다"* 는 **그 외의 경우에는 맞다**를 함의한다. E-1 만 적용하면 같은
파일 안에서 **본문과 그 본문에 관한 Rationale 이 서로 다른 축을 말하는** 상태가 남는다.

**처방은 append 다 — 기존 항목을 지우지 않는다.** 그 항목의 구조적 결정("복제 말고 위임")은
지금도 유효하고, 틀린 것은 그 결정을 뒷받침하는 **진단 문장**이다. 관례 실측: 이 저장소는
낡은 Rationale 에 `> **(YYYY-MM-DD 갱신)**` 블록쿼트를 덧붙인다 — **인스턴스 2건**, 둘 다
`6-websocket-protocol.md`(2026-08-14 갱신 · 2026-08-16 보강). `2-api-convention.md` 에는 0건이라
이 문서로서는 첫 사례다. (`rationale_continuity` 는 "3건 이상" 이라 했는데 실측은 2건이다.)

```markdown
> **(2026-09-10 갱신 — 위 진단이 한 칸 좁았다)** 위 첫 문장은 두 요약 줄이 *"**서버가 스스로
> 끊은 경우**에는 틀리다"* 고 적어 **그 외의 경우에는 맞다**를 함의했다. 틀렸다 — 두 줄은
> **모든 경우에** 틀렸고, §10.4 본문을 그에 맞춰 교체했다.
>
> - 백오프 수치 `(1s, 2s, 4s, … 30s)` 는 [WS 프로토콜 §6.1](./6-websocket-protocol.md#61-클라이언트-재연결-socketio-내장)
>   이 스스로 *"spec 초안 값이며 실제는 Socket.IO Manager 의 내장 알고리즘을 따른다"* 고 부인한 값이다.
> - last-event-ID 재전송은 **native WS 에 아예 없다.** 끊긴 원인과 무관하게 복구는 항상
>   `execution.snapshot` 이고([§6.2](./6-websocket-protocol.md#62-놓친-이벤트-복구)), `seq` 기반
>   replay 버퍼는 EIA SSE 어댑터가 소유한다([§4.7](./6-websocket-protocol.md#47-외부-표면-매핑-external-interaction-api)).
>   **이 사실은 새로 밝혀진 것이 아니다** — WS 프로토콜 Rationale 「재연결 복구 — native WS 는
>   snapshot, seq 버퍼-replay 는 SSE 전송」이 **2026-05-31** 에 이미 *"native WS lastSeq
>   버퍼-replay 전면 구현"* 을 폐기 대안으로 기록했다. 위 2026-09-02 판단은 그 폐기 선언을
>   인용하지 않은 채 "전송 계층 끊김" 이라는 부분집합에 그 설계를 남겨 뒀다.
>
> **위임한다는 결정 자체는 유지된다** — 바뀐 것은 위임 대상이 "예외 하나" 가 아니라 **재연결·복구
> 서술 전체**라는 것이다.
```

**왜 새 서브섹션이 아니라 append 인가**: `convention_compliance` 는 새 서브섹션을 권했다. 그러나
주제가 같은 항목이 이미 있으므로 새로 만들면 **§10.4 를 다루는 Rationale 이 두 개**가 되고, 그건
이 문서가 §10 에서 피하려는 바로 그 형태(같은 것을 두 자리에 두기)다. 기존 항목에 붙이면 이력이
한 자리에 남는다.

## 무엇을 하지 않나

- **§10.1·§10.2·§10.3 은 건드리지 않는다** — 다만 근거가 소절마다 다르다
  (`convention_compliance` INFO 가 내 뭉갠 서술을 갈랐다):
  - **§10.2** 의 `{ type, payload }` 는 `6-websocket-protocol.md §1` 註가 **논리적 추상화로 명시
    처리**한 표기다. "틀렸다" 가 아니라 이미 설명된 자리다.
  - **§10.1** 의 `ws(s)://…?token=` 은 애초에 **틀리지 않았다.** §1.1 엔드포인트 + §1.2 가
    **채택한** 쿼리 파라미터 인증을 합친 정확한 요약이다 — §1 註가 비채택으로 지목한 것은
    §1.2 의 **서브프로토콜** 인증이고 쿼리 파라미터가 아니다. 처음 이 자리에 "§1 註 하나가 둘을

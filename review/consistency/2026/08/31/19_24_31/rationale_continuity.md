# Rationale 연속성 검토 — spec/5-system/ (impl-done)

## 검토 범위 확인

번들 프롬프트의 `## 구현 변경 사항`(코드 diff, 9파일/277줄) 섹션이 컨텍스트 예산으로
완전히 누락되어 있었고, target 인 `spec/5-system/14-external-interaction-api.md` 본문도
"예산 초과로 생략" 표시만 있었다. 프롬프트 지시대로 판정을 프롬프트만으로 내리지 않고,
워킹트리에서 직접 `git diff origin/main...HEAD`(spec + code 양쪽)를 떠서 실제 델타를
확인했다.

**실측 델타** (origin/main → HEAD):
- `spec/5-system/6-websocket-protocol.md` — 70줄 변경 (섹션 재배치 + 번호 정정)
- `spec/5-system/14-external-interaction-api.md` — 5줄 변경 (HMAC 알고리즘 화이트리스트 정정 + 상호참조 번호)
- `spec/data-flow/8-notifications.md` — 10줄 변경 (상호참조 번호 동반 정정, scope 밖이나 확인함)
- 코드 9파일/277줄 — 전부 `§4.4`/`§4.5` 등 절 번호를 가리키는 JSDoc/주석 갱신 + 줄번호 인용 제거. 동작 변경 없음 (`workflow-assistant.controller.ts` 의 401 부착 1건만 예외이나 spec/5-system 범위 밖).

## 발견사항

없음. 이 델타는 두 종류의 순수 정합화 작업이며, 어느 쪽도 과거 Rationale 을 번복·우회하지 않는다.

1. **WS §4 절 번호 재정리** (`6-websocket-protocol.md`) — 중복이던 `### 4.4`(사용자 입력 대기
   상세 / 알림 이벤트) 중 인용 0건인 "KB 문서 이벤트"(구 §4.3, 실제로는 §4.4 뒤에 있었음)를
   §4.2 뒤로 옮기고 꼬리 3절(알림 §4.4→4.5, 시스템 §4.5→4.6, 외부 표면 매핑 §4.6→4.7)을 민
   것. 이 작업 자체가 **커밋 메시지에서 2026-08-24 에 이미 기록된 유예 결정**("절 번호 재정리는
   문서 전체의 링크를 훑어야 해서 doc 묶음에 얹을 크기가 아니다")을 실행에 옮긴 것으로,
   과거 결정을 뒤집는 게 아니라 완결한다. 재검증 결과 (a) `spec/` 저장소 전체에서 옛 앵커
   (`#44-알림-이벤트`, `#46-외부-표면-매핑`)를 가리키는 잔존 참조가 0건이고, (b) §4.4(사용자
   입력 대기)는 번호·앵커 모두 그대로라 인용 ~190건이 전혀 깨지지 않았다. Rationale 섹션
   내부의 §4.4/§4.5/§4.6 상호참조도 전수 갱신되어 있다(§Rationale `R-wontdo-rawws-rest`
   "잔여(Planned)" 항목 등).
2. **EIA §8.2 HMAC 알고리즘 화이트리스트 확장** (`14-external-interaction-api.md`) — 본문이
   "`hmac-sha256` 만" 이라 적던 것을 "`hmac-sha256` / `hmac-sha512` 두 값" 으로 넓혔다. 이는
   **같은 문서의 기존 `## Rationale` §R12**("각 경로에서 algorithm 화이트리스트는 `sha256`/
   `sha512` 만 (둘 다)")와 이미 존재하던 EIA-NX-03, 그리고 구현
   (`notification-signature.util.ts` 의 `SupportedHmacAlgorithm = 'hmac-sha256' | 'hmac-sha512'`)
   양쪽과 정합시키는 **자기 문서 내부 drift 교정**이다 — §8.2 자체가 자기 문서의 R12 보다
   좁았던 stale 서술이었음을 `git log -S`로 확인(원문은 스펙 최초 작성 커밋 `#228` 산물이고
   R12 는 그보다 나중에 §8.2 를 갱신하지 않은 채 추가됐다). 새 값을 "채택된 결정" 으로
   재도입한 게 아니라 이미 채택돼 있던 R12 를 본문이 뒤늦게 따라잡은 것이므로 기각된
   대안의 재도입이 아니다. `v2=` 서술도 삭제가 아니라 스킴버전(§6.1)·secret rotation
   컬럼(§7.1)과 축을 분리해 재작성했을 뿐 정보 손실이 없다.

두 변경 모두 (a) 기존 Rationale 이 이미 승인한 내용을 본문에 반영하거나 (b) 순수 구조적
재배치이며 설계 결정 자체를 바꾸지 않는다. `R-wontdo-rawws-rest`, R7(seq 공유), R12,
R13, "§4.4 wire 필드 caveat", "`resumed` 의미 재정의" 등 실제 설계 결정을 담은 Rationale
항목은 본문·수치 참조만 갱신됐을 뿐 결론이 하나도 바뀌지 않았다.

## 요약

이번 impl-done 델타는 WebSocket/EIA 두 spec 문서에서 (1) 중복·역순이던 절 번호를 정리하고
(2) 자기 문서의 Rationale(R12)보다 좁게 적혀 있던 본문 한 줄을 그 Rationale 수준으로
넓히는 두 건의 정합화 작업이다. 둘 다 새로운 설계 판단이 아니라 이미 기록된 결정
(2026-08-24 유예된 재배치 결정, 기존 R12)을 뒤늦게 실행/반영한 것이며, 관련 코드 9개
파일의 변경도 이 절 번호 갱신을 따라가는 주석·JSDoc 수정뿐이다. 저장소 전체에서 옛 절
번호/앵커에 대한 잔존 참조가 없음을 grep 으로 확인했고, 과거 Rationale 이 명시적으로
기각한 대안이 다시 채택되거나, 합의된 설계 원칙이 훼손되거나, 근거 없이 결정이 번복된
사례는 발견되지 않았다.

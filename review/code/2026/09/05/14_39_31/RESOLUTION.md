## C1 — 재현부터 했고, 결함이 맞았다

`SelfDto { id, self?: SelfDto | null }` 로 프로브를 세워 실측했다:

| 입력 | 종전 결과 |
|---|---|
| `{ id:'a', self:{ leak:1 } }` | `[]` |
| `{ id:'a', self:{ id:'b', self:{ leak:2 } } }` | `[]` |

자기참조 DTO 아래는 **어느 깊이도 검사되지 않았다.** 검증자가 조용히 거짓 통과를 내는 것은
이 도구가 애초에 잡으려던 결함과 **같은 클래스**다.

### 개념이 틀렸다 — 재귀를 묶는 것은 payload 이지 스키마가 아니다

재귀는 payload 를 따라 내려가고, HTTP 응답은 파싱된 JSON 이라 **비순환·유한**이므로 스스로
끝난다. 자기참조 *스키마* 는 그 자체로 순환이 아니다 — 값이 어느 깊이에서 반드시 끊긴다.
진짜 무한 위험은 **값 그래프**의 순환(메모리 안에서 만든 자기참조 객체)이다.

그래서 방문 집합을 스키마 이름에서 **현재 경로의 payload 객체 동일성**으로 바꿨다. 스키마
재귀는 깊이 제한 없이 열리고, 자기를 가리키는 객체는 여전히 끝난다.

### 내 테스트가 vacuous 했다는 지적도 맞다

*"순환 참조에서 무한히 내려가지 않는다"* 는 **완전히 유효한** payload 만 대조했다. 아래를
아무것도 검사하지 않아도 통과하는 형태다 — 통과가 두 상태(검사했고 맞았다 / 애초에 검사하지
않았다)를 구분하지 못했다. 이제 셋으로 나눴다:

| 테스트 | 무엇을 가르는가 |
|---|---|
| 자기참조 첫 단계 내부가 검사된다 | `['self.id:missing','self.leak:undeclared']` — 종전엔 `[]` |
| 깊이 제한 없이 내려간다 | `['self.self.id:missing','self.self.leak:undeclared']` — 이름-기반 가드로는 못 얻는다 |
| 자기를 가리키는 payload 에서도 끝난다 | 종료 자체 (원래 막으려던 것) |
| 유효한 자기참조 payload 는 통과한다 | 거짓 위반이 없다 |

## W5 — 출처를 §5.4 로 적은 것이 틀렸다

§5.4 원문(`spec/5-system/2-api-convention.md`)은 응답 바디에 대해 이렇게 적는다:

> **키를 생략**하는 필드 → `@ApiPropertyOptional()` + `field?: T` (`| null` 금지)

그리고 그 조합이 정당한 곳을 요청 바디로 명시한다 — *"요청 DTO 에서는
`@ApiPropertyOptional({ nullable: true })` + `field?: T | null` 조합이 정당하다"*.

즉 응답 DTO 가 그 조합을 선언하고 있다면 **그것 자체가 선언 층의 §5.4 위반**이고, 이 도구가
판정할 대상이 아니다. 이 도구는 **응답 값 vs 그 필드의 선언**을 본다. 값 검사기가 선언을
무시하고 `null` 을 위반이라 부르면 이미 알려진 선언 drift 마다 거짓 위반이 쏟아진다.

표의 출처 열을 그 경계로 다시 그렸다 — §5.4 인 행과 아닌 행(§ nullable 예외 · undeclared
확장)이 눈으로 갈린다.

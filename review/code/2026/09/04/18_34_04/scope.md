# 변경 범위(Scope) 리뷰

## 대상 변경 요약

단일 작업: `GET /api/executions/workflow/:workflowId` 의 죽은 쿼리 파라미터 `workflowId` 제거
(`plan/in-progress/spec-draft-nullable-notation-followups.md` 의 후속 항목, 사용자가 선택한
"옵션 A: 제거"). 4개 파일이 이 단일 작업에 결속돼 있다.

## 발견사항

### 파일별 범위 대조

- **파일 2 (`query-execution.dto.ts`)** — 요청된 변경 그 자체다. `workflowId` 필드·데코레이터
  제거와 함께 이제 쓰이지 않는 `IsUUID`(class-validator) import, `Transform`(class-transformer)
  import 전체를 제거했다. 전체 파일 컨텍스트로 확인한 결과 두 심볼은 다른 곳에서 쓰이지 않으므로
  이 import 정리는 필드 제거의 직접적·필수적 부산물이지 별도의 임포트 정리 리팩토링이 아니다.
  범위 내.

- **파일 3 (`swagger-dto-contract-guard.ts`)** — `@Transform` 예외 조항의 JSDoc 만 수정한
  comment-only diff다. 이 주석이 예시로 들던 필드가 바로 `QueryExecutionDto.workflowId` 였고,
  그 필드가 이번 변경으로 제거되어 예외의 "산 예시"가 사라졌다(실사례 18→17건, 그중 축이 갈리는
  건 1→0). 주석을 현재 사실에 맞게 갱신하는 것은 제거 작업의 직접적 후속이며, 코드 로직 변경은
  없다. 범위 내 — "불필요한 주석 변경"에 해당하지 않는다(사실이 바뀌어 필연적으로 갱신이 필요).

- **파일 1 (`CHANGELOG.md`)** — 신설 Unreleased 항목은 오직 `workflowId` 제거 건만 다룬다.
  본문(영향·소비자 실측·guard 예외 부수 효과)이 파일 2·3 의 변경과 1:1로 대응하며, 무관한 내용은
  섞여 있지 않다. 항목이 다소 길지만(표 2개 + 소비자 실측 + guard 부수 설명), 같은 CHANGELOG
  파일의 기존 다른 Unreleased 항목들도 동일하게 상세한 서술·표·영향 분석을 관례로 쓰고 있어
  (프로젝트 컨벤션과 일치), 이 길이 자체를 범위 이탈로 보기는 어렵다. 범위 내.

- **파일 4 (`spec-draft-nullable-notation-followups.md`)** — 해당 plan 문서의 "후속" 체크리스트
  중 정확히 이 작업 항목([ ] → [x])만 갱신했고, 하단 "종결 조건" 표의 같은 행도 취소선 +
  "종결(2026-09-04)" 로 함께 갱신했다(다른 열린 항목 3건은 손대지 않음). CLAUDE.md 의
  plan-lifecycle 관례("체크박스=실제 상태", "본문 체크박스 + 하단 표 양쪽 동기화")를 정확히 따른다.
  범위 내.

### 파일 간 교차 검증

- CHANGELOG(파일 1)·plan(파일 4) 두 문서에 거의 동일한 서술(죽은 필드 판정 근거, 소비자 실측,
  guard 예외 0건화)이 중복 기재돼 있다. 다만 이는 "사용자/개발자 대상 변경 로그"와 "내부 작업
  추적 문서"라는 서로 다른 목적의 문서이고, 두 문서 모두 이 프로젝트의 표준 산출물이므로 중복
  자체는 스코프 이탈이 아니라 관례적 이중 기록으로 판단한다.
- `spec/` 하위 파일은 이번 diff 에 전혀 포함되지 않았다(순수 `codebase/` + `plan/` 변경). 이
  작업은 CLAUDE.md 상 developer 권한 범위(`codebase/**`, `plan/**`) 안에 있고 planner 턴이
  필요한 spec 변경은 없다 — 역할 경계 위반 없음.
- 파일 3 의 갱신된 JSDoc 이 언급하는 `[대조군] @Transform 예외` 픽스처(`swagger-dto-contract.spec.ts`)
  자체는 이번 리뷰 대상 4개 파일에 포함돼 있지 않다. 주석상 "픽스처가 양방향으로 고정함을
  뮤테이션으로 확인했다" 는 서술은 그 파일이 이미 존재해 별도 수정이 불필요했거나(픽스처가
  일반화돼 있어 필드 제거 자체로 영향받지 않음), 혹은 이 리뷰 배치에서 누락됐을 가능성 둘 다
  있다 — 다만 이는 "범위 초과"가 아니라 잠재적 "누락"의 문제라 스코프 리뷰의 발견사항으로
  올리되 등급은 낮게 잡는다.

## 요약

리뷰 대상 4개 파일(CHANGELOG.md 신규 항목, DTO 필드+미사용 import 제거, 그 필드를 참조하던
repo-guard JSDoc 갱신, plan 체크리스트 갱신)은 전부 "죽은 `workflowId` 쿼리 파라미터 제거"라는
단일 작업으로 정확히 수렴한다. 요청 외 리팩토링·기능 확장·무관한 파일 수정·포맷팅 잡음은
발견되지 않았고, import 정리와 guard 주석 갱신은 필드 제거의 직접적·필연적 부산물이다. CHANGELOG
항목의 상세도는 프로젝트의 기존 관례와 일치한다. 유일한 잠재 이슈는 guard 주석이 언급하는
`swagger-dto-contract.spec.ts` 픽스처 변경이 이번 리뷰 배치에 없다는 점인데, 이는 스코프 초과가
아니라 커버리지/누락 여부를 확인할 필요가 있는 INFO 수준 사안이다.

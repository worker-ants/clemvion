## 요약

이번 변경은 범위가 매우 작고(`codebase/` 기준 6개 파일, +89/-2줄) 목적이 단일하다 — 인덱스 마이그레이션 1개(V111) 추가와 `TriggerResourceReleaserService.releaseExternalForParent`의 `select` 컬럼 좁히기 1건. 신규 서비스 코드(`releaseExternalForParent`)는 짧고 단일 책임이며, JSDoc이 "왜 이 세 컬럼만 싣는가"·"config를 빼면 무엇이 조용히 깨지는가"를 명시해 다음 사람이 실수로 컬럼을 더 줄이는 것을 막아 준다. 대응하는 단위 테스트 역시 왜 이 대조가 필요한지(mock이 select 여부와 무관하게 전체 객체를 돌려주므로 `find` 인자 정확 대조만이 유일한 방어선) 주석으로 설명해 두어 향후 유지보수자가 이 단언을 vacuous라고 오판해 지우는 것을 방지한다. 마이그레이션 SQL/.conf 파일은 직전 선례(V110)의 형식·주석 구조를 그대로 따르고 있어 컨벤션 일관성이 높고, README 컨벤션 절 갱신도 표·코드블록으로 구조화되어 있다. e2e 스키마 단언도 V110 선례와 동일한 패턴(존재 여부가 아니라 `indisvalid`까지 확인)을 재사용해 중복이라기보다 의도된 재사용 패턴이다. 함수 길이·중첩 깊이·매직 넘버·순환 복잡도 모두 문제될 수준이 아니며, 발견된 두 건은 모두 INFO 수준(문장 길이 누적 추세, 문서 중복 확대 추세)으로 즉시 조치가 필요한 결함이 아니다.

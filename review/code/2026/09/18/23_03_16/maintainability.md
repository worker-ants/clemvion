# 유지보수성(Maintainability) 리뷰

## 리뷰 범위

`codebase/backend/migrations/V121~V130`(각 `.conf`+`.sql` 10쌍, 신규) ·
`codebase/backend/test/deletion-cascade-indexes.e2e-spec.ts`(확장) ·
`spec/1-data-model.md`(Rationale 신설 절 + 상호참조 보정) · 관련 `spec/data-flow/*.md` ·
`plan/`·`review/consistency/**` 산출물. 코드 성격상 핵심 검토 대상은 `codebase/**`(마이그레이션·테스트)이며,
`plan/**`·`review/consistency/**`는 프로세스 산출물이라 유지보수성 관점(가독성/네이밍/함수 길이/중첩/매직넘버/중복/복잡도)의
적용 대상이 제한적이라 부차적으로만 다뤘다.

## 발견사항

- **[INFO]** 마이그레이션 헤더 주석(비-트랜잭션 근거 문단)이 10개 파일에 **바이트 단위로 완전히 동일**하게 반복된다.
  - 위치: `codebase/backend/migrations/V121__edge_target_node_id_index.sql:17-20` 를 비롯해
    V122~V130 `.sql` 10개 파일 전부 동일 4줄("비-트랜잭션 (executeInTransaction=false, 동봉 .conf) — …
    (migrations/README.md §5 «신규 추가에도 0) 을 둡니다», 선례 V111~V120).")이 `grep -h ... | sort -u`
    결과 1종으로 확인됨.
  - 상세: 이 자체는 새로 도입된 패턴이 아니라 `V111~V120`(선례)에서 이미 확립된 마이그레이션 파일 관례를
    그대로 답습한 것이다(예: `V115__llm_usage_log_node_execution_id_index.sql` 도 동일 문구, 참조 대상
    파일명만 다름). 마이그레이션은 append-only 이력이라 파일마다 자기완결적 설명을 남기는 것이 의도된
    trade-off 로 보이며, 각 `.conf` 파일의 `.sql` 파일명 상호참조도 10곳 전부 정확했다(교차 확인 완료,
    복붙 오류 없음). 다만 이 컨벤션 문구 자체(README.md §5 인용) 를 나중에 수정해야 할 경우 이미
    20개(V111~V130) 파일을 손으로 동기화해야 하는 비용은 그대로 누적된다.
  - 제안: 현재 방식을 바꿀 필요는 없음(기존 컨벤션과 일관). 다만 향후 이런 정형 boilerplate 가
    더 늘어날 것이 예상되면, `migrations/README.md` 링크만 남기고 반복 문단을 짧게 줄이는 리팩터링을
    별도 트래커 항목으로 검토할 만하다 — 이번 PR 의 책임 범위는 아니다.

  글머리 기호 목록이 아니라 긴 산문 문단 안에 굵게 표시된 레이블로 배치해 스캔하기 다소 어렵다.
  - 위치: `spec/1-data-model.md` `## Rationale` → `### 쓸 인덱스가 없는 FK 서른하나의 처분 (2026-09-18)` 절,

  - 상세: 정보 밀도는 높지만 표(table)와 병기되어 있어 참조 자체는 가능하고, 같은 파일의 다른 Rationale
    절들(예: 앞선 "삭제 연쇄의 FK 인덱스 다섯", "그래프 RAG 삭제 연쇄의 FK 인덱스 넷")도 동일하게 조밀한

## 요약

이번 변경은 신규 마이그레이션 10쌍과 이를 뒷받침하는 e2e 테스트 확장이 중심이며, 둘 다 기존 코드베이스의
확립된 관례(`V111~V120` 마이그레이션 헤더 패턴, `it.each` 테이블 기반 e2e 단언)를 그대로 따르고 있어
가독성·네이밍·일관성 면에서 매우 안정적이다. 함수 길이·중첩 깊이·순환 복잡도는 대부분 순수 DDL 이라 해당
사항이 없고, 유일한 e2e 테스트 로직도 짧고 단일 책임(정의+`indisvalid` 대조)을 유지한다. 인덱스 이름
(`idx_<table>_<column[, column]>`)과 파일명 규칙도 10개 전부 일관되며 상호참조 오류가 없음을 직접 확인했다.
가장 눈에 띄는 특징은 마이그레이션 헤더의 대량 반복 주석인데, 이는 이번 PR 이 새로 만든 패턴이 아니라
선례를 계승한 의도된 컨벤션이라 결함으로 보기 어렵다. spec 문서의 신규 Rationale 절은 정보 밀도가 높지만
표와 함께 구조화되어 있고 기존 절들과 스타일이 일관된다. 전반적으로 유지보수성 리스크는 낮다.

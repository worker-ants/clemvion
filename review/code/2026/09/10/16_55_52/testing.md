# 테스트(Testing) 리뷰 — `trigger-workflow-ref` 캐너리 (4라운드)

대상: `codebase/backend/src/shared/testing/trigger-workflow-ref.spec.ts` /
`trigger-workflow-ref.ts`. 오케스트레이터 지시대로 **좁게** 4개 항목만 검증한다.

## 검증 방법

뮤테이션 없이 `git diff`(정적 대조)와 `Read`(전체 파일 열람) 만으로 끝냈다 — 이번 델타가
주석·라벨 전용이라는 것을 diff 로 먼저 확인했고, 확인된 이상 assertion/fixture 는 애초에
바뀌지 않았으므로 재-뮤테이션할 대상이 없다. 3라운드(`review/code/2026/09/10/16_26_57`)가
이미 남긴 뮤테이션 실측(`12/12 GREEN` 등)을 정본으로 삼아 이번 라운드의 주석 서술이 그 실측과
글자 단위로 일치하는지만 대조했다. 저장소 파일은 전혀 건드리지 않았다 — `cp` 백업/뮤테이션
자체가 불필요했다.

## (1) "단언·fixture·테스트 바디는 한 글자도 안 바뀌었다" — 참으로 확인

`git diff -U0 64334e708 HEAD -- <두 파일>` 로 변경된 줄만 추출했다. 결과는 전부 다음 형태뿐이다:

- `spec.ts` 헤더 JSDoc 블록(`* >` 로 시작하는 줄) — 가드 목록 10→11 정정 + ⑤ 예외 서술 추가.
- `spec.ts` 인라인 `// ── 가드 N: ... ──` / `## 가드 N: ...` 주석의 숫자만 변경(5→6, 6→7, 7→8,
  8→9, 9→10, 10→11) + `null` 케이스 앞에 신규 JSDoc 블록(`## 가드 ③·⑤`) 삽입.
- `trigger-workflow-ref.ts` 파일 스코프 주석의 "세 번" → "네 번" 정정 + 부연 3줄.

`expect(`, `it(`, fixture 리터럴(`WITH_WORKFLOW`/`WITHOUT_WORKFLOW`/`WF_ID` 등), `describe(` 블록
구조 — 이들 중 어느 것도 diff 에 등장하지 않는다. `git diff --stat` 도 `37 insertions(+), 16
deletions(-)` 로, 두 파일 모두 순수 주석 라인 수 증가와 일치한다. **주장은 참이다.**

## (2) ⑤ 예외 서술이 3라운드 실측과 정확히 일치하는지 — 세 주장 모두 글자 단위로 일치

키셋 검사가 대신 던짐)과 동일하다. **과장·축소 없이 3라운드 실측을 정확히 반영한다.**

추가로 인라인 JSDoc(`spec.ts:102-105`, `## 가드 ③·⑤`)의 "이 케이스가 실제로 무는 것은 ③
쪽뿐이다" 도 같은 3라운드 결론("`null` 은 부재가 아니다 테스트는 여전히 통과하지만 그 원인이
`ts:123`(⑤)이 아니라 `ts:126`(⑥)이다")과 일치한다.

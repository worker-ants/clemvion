# 변경 범위(Scope) 리뷰 — schedule-trigger e2e 「D. PATCH cron」 flake 수정

## 리뷰 방법

`git diff origin/main..HEAD --stat` 로 실제 변경 파일군을 전수 대조했다(저장소 파일은 건드리지 않음, 읽기 전용).
프롬프트에 나열된 63개 "파일" 은 다음 5개 디렉터리로만 나뉜다 — 이 밖의 디렉터리(프론트엔드·설정·CI 등)는 diff 에 전혀 등장하지 않는다.

| 분류 | 파일 수 | 변경량 |
|---|---|---|
| `codebase/backend` (실제 애플리케이션 코드) | 1 | +26 / -3 |
| `plan/complete`, `plan/in-progress` (작업 추적) | 2 | +86 / -1 |
| `review/code/2026/09/20/{11_54_10,12_17_18,12_45_31,13_12_35}/*` (`/ai-review` 4라운드 산출물) | 47 | 나머지 대부분 |
| `review/consistency/2026/09/20/{11_21_16,13_34_15}/*` (`--impl-prep`/`--impl-done` 산출물) | 13 | 나머지 대부분 |

총 3575줄 추가 중 실제 애플리케이션 코드 변경은 **26줄** 뿐이고, 나머지는 이 저장소의 명시 규약(`CLAUDE.md` "정보 저장 위치" 표 — 코드 리뷰 산출물은 `review/code/**`, 일관성 검토 산출물은 `review/consistency/**` 에 커밋)에 따라 자동 생성·커밋되는 워크플로 산출물이다. 파일 수(63)만 보면 범위가 커 보이지만 이는 리뷰 라운드가 반복될 때마다 세션 디렉터리가 통째로 새로 생기는 이 저장소의 구조적 특성 때문이며, scope 위반의 신호가 아니다.

## 발견사항

### 1. 애플리케이션 코드 변경 (`codebase/backend/test/schedule-trigger.e2e-spec.ts`)

- 변경은 `describe('Schedule trigger (e2e)', ...)` 안의 단일 `it('D. PATCH cron → nextRunAt 재계산', ...)` 케이스에 **국한**된다. 같은 파일의 다른 케이스(A·C·E·G·H 등)는 손대지 않았다.
- 변경 내용은 세 가지뿐이다: (1) 생성 cron 리터럴 교체(`0 10 * * *` → `0 0 1 1 *`), (2) 판정 로직 교체(`not.toBe(originalNext)` → 시간창 + 초 자리 검증), (3) 그 판단 근거를 설명하는 JSDoc/인라인 주석. 셋 다 "하루 1분 창에서 거짓 실패한다" 는 원 결함과 직결된다 — 서비스 코드(`schedules.service.ts` 등)는 diff 에 등장하지 않는다.
- import 구문·포맷팅·무관 리팩토링·기능 추가는 없다. `patchedAt`/`nextRunMs` 두 변수만 새로 도입됐고 모두 새 단언에 쓰인다.
- **[정보 확인, 발견사항 아님]** JSDoc 안에 "남는 잔여" 로 언급된 "반대 방향의 좁은 창"(연말 ~2분 거짓 통과)은 **이번 케이스를 고치지 않고** 트래커에 별도 항목으로만 등재했다 — 단위 테스트로 닫아야 할 잔여를 이번 e2e PR 범위에 욱여넣지 않은 것은 scope 관점에서 올바른 판단이다.

### 2. Plan/트래커 변경

- `plan/complete/schedule-cron-flake.md` 는 이번 작업 자체의 작업 기록(신규 plan)으로, 본문이 실제 diff(cron 교체 + 판정 교체)와 정확히 대응한다. 스코프를 벗어나는 서술은 없다.
- `plan/in-progress/spec-draft-nullable-notation-followups.md` 에서 **체크된 항목**(「D. PATCH cron」 flake)은 정확히 이번 작업이 해소한 항목이다. **새로 추가된 두 항목**(`NAV-WF-02`/`NAV-WF-06` 카탈로그 불일치, cron 재계산 happy-path 단위 테스트 부재)은 이번 코드 변경 범위 밖 이슈를 **직접 고치지 않고 백로그로만 등재**한 것 — `--impl-prep` consistency-check(`NAV-WF-02`)와 자체 리뷰 라운드(단위 테스트 항목)가 발견한 별개 이슈를 이번 PR 이 떠안지 않고 분리한 정상적인 처리다. 두 항목 모두 실제 코드 변경을 동반하지 않는다.

### 3. 리뷰/일관성 검토 산출물

- `review/code/2026/09/20/{11_54_10,12_17_18,12_45_31,13_12_35}/*` 와 `review/consistency/2026/09/20/{11_21_16,13_34_15}/*` 는 이 작업의 `/ai-review` 4라운드 + `--impl-prep`/`--impl-done` 각 1회 실행이 만든 산출물이다. `CLAUDE.md` 가 이를 저장소에 커밋되는 표준 산출물로 명시하고 있고("코드 리뷰 산출물"/"일관성 검토 산출물" 행), plan 체크리스트도 각 라운드를 항목별로 대응시키고 있어 이번 작업과 무관한 별도 검토 세션이 섞여 들어온 흔적은 없다.

## 확인했으나 문제 없음

- 임포트 변경: 없음(diff 에 `import` 라인 없음)
- 설정 파일 변경: 없음(`package.json`, CI, env 등 diff 에 등장하지 않음)
- 포맷팅-only 변경: 없음 — 모든 변경 라인이 실질 로직/주석 변경과 결합돼 있음
- 기능 확장(over-engineering): 없음 — 새 헬퍼·유틸·추상화 도입 없이 기존 `it()` 블록 내부만 수정

## 요약

실제 애플리케이션 코드 변경은 `schedule-trigger.e2e-spec.ts` 의 단일 테스트 케이스(D)에 정확히 국한되어 있고, cron 리터럴·판정식·설명 주석 세 가지 모두 "하루 1분 창 거짓 실패" 라는 신고된 결함과 직결된다. plan 트래커에 추가된 두 백로그 항목은 이번 PR 이 발견했지만 직접 고치지 않고 분리 등재한 것으로 scope 관점에서 적절하다. diff 의 절대 다수(63개 파일 중 60개)는 이 저장소가 규약으로 명시한 리뷰/일관성 검토 워크플로 산출물이며 애플리케이션 스코프와 무관한 프로세스 기록이다. 범위 이탈·불필요한 리팩토링·무관한 파일 수정·설정 변경은 발견되지 않았다.

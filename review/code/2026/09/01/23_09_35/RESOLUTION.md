## INFO 1 (requirement) — 내 PR 본문 주장이 실제보다 넓었다

리뷰어가 커밋된 `error-codes.md` 문구와 **6차 `--spec` 라운드가 검증한 스냅샷 문구**가 축어적
으로 다름을 짚었다. 확인했다 — 사실이다:

| | 문구 |
|---|---|
| 6R 검증 draft | 경계는 **누가 발행하는가**이며, 카탈로그 분류와 1:1 대응하지 않는다 |
| 커밋된 spec | 경계는 **비대칭**이다: `EngineErrorCode` 는 엔진만, `ErrorCode` 는 엔진도 |

**주장 자체는 소스로 직접 재검증했다** — 리뷰어 말을 받아쓰지 않고 내가 grep 했다:
`EngineErrorCode.` 는 `execution-engine/` 2파일에서만 쓰이고(`execution-engine.service.ts`,
`shutdown/shutdown-state.service.ts`), `ErrorCode` 멤버인 `EXECUTION_TIME_LIMIT_EXCEEDED` 는
`execution-engine.service.ts` 에서도 쓰인다. 비대칭 서술은 맞다.

**틀린 것은 내 PR 본문의 근거 표현이었다.** "`--spec` 6R 최종 BLOCK: NO" 를 커밋 문구의 보증
처럼 적었는데, 6R 이 본 것은 **다른 문장**이다. 게이트가 검증한 범위를 넘겨 인용했다 —
`git log -S` 로 실측하지 않고 "라운드를 돌았으니 통과한 것" 으로 뭉뚱그린 것과 같은 결함이다.

PR 본문을 고쳤다: 6R 이 검증한 것은 draft 이고, 최종 문구는 그 뒤 다듬었으며, **주장은 소스로
독립 재검증했다**고 분리해 적었다.

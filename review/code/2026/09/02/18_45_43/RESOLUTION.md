# RESOLUTION — `auth.token_expired` 구현 리뷰 3라운드

대상 SUMMARY: 위험도 **MEDIUM** · Critical **0** · Warning **4** · INFO 18

**WARNING 4건 전부 조치.** 그 과정에서 **내 테스트가 `undefined` 를 기다리고 있었다**는 것을
발견했다 — 3R 의 두 지적을 고치려다 나온 것이고, 앞선 라운드의 단언들도 같은 약점을 안고
있었다.

## W1 (concurrency) — cross-generation race

`refreshAndReconnect` 가 클로저 공유 변수 `socket` 을 `await` **뒤에** 참조한다. 그 사이
`connect()` 가 다시 불리면(재마운트 등) 옛 세대의 재발급이 **새 소켓을 끊고 다시 붙인다** —
이 PR 이 막으려던 "보이는 끊김" 이 다른 경로로 재현된다. 리뷰어가 격리 재현했다.

두 가지를 함께 넣었고, **둘 다 필요하다는 것을 뮤테이션으로 갈랐다**:

| 장치 | 막는 것 |
|---|---|
| `const mySocket = socket` 스냅샷 | 옛 재발급이 **새 소켓**을 건드리는 것 |
| `socket !== mySocket` 비교 | 버려진 **옛 소켓을 되살려** 소켓이 둘이 되는 것 |

> **초판 테스트는 스냅샷만 검증했다.** 세대 비교를 지우는 뮤턴트가 **생존**했다 — 새 소켓은
> 여전히 안전했기 때문이다. `gen1.connect` 가 안 불리는지까지 단언하고 나서야 갈렸다.
> **"고쳤다" 를 한 축으로만 확인하면 나머지 축은 무증거로 남는다.**

테스트 mock 도 고쳤다 — `io` 가 매번 **같은 인스턴스**를 돌려주면 세대 교체를 재현할 수 없다.

## W2 (testing) — 가드 리셋이 무검증이었고, 고치다 진짜 버그를 만났다

`inFlight` 의 `.finally` 리셋을 지워도 24/24 GREEN 이었다(리뷰어 실측). 이 회귀가 들어오면
최초 1회 갱신 뒤 세 트리거가 **영구히 무시돼** 두 번째 900초 주기부터 "만료 후 무기한 인가" 가
조용히 재발한다.

테스트를 넣자 **RED 가 났는데, 이유가 내 예상과 달랐다.**

핸들러가 `void refreshAndReconnect(...)` 로 promise 를 버려서, 테스트의 `await handler()` 는
**`undefined` 를 기다리고 있었다.** 단언이 실제 작업보다 먼저 돌았다 — 앞선 라운드의 겹친
트리거·재발급 실패 테스트도 같은 약점을 안고 있었고, 마침 microtask 순서가 맞아 통과했을 뿐이다.

세 핸들러가 promise 를 **반환**하게 고쳤다(socket.io 는 반환값을 무시하므로 무해하다).
그러고 나서야 리셋 뮤턴트가 **RED** 로 갈렸다.

## W3·W4 — 들여쓰기·낡은 주석

- **W3** 2R 에서 `inFlight` 가드를 감싸며 안쪽을 재인덴트하지 않아 `try/catch` 가 화살표
  함수의 형제처럼 보였다. 실제 중첩에 맞춰 들여썼다. 동작 무관이지만 **다음 리팩터링의 스코프
  오독**이 정확히 이 자리에서 난다.
- **W4** `connect()` 상단 pending-가드 주석이 *"토큰 갱신 재연결은 `connect_error` 핸들러가
  담당"* 이라고만 적고 있었다. 1R 에서 세 트리거를 공유 헬퍼로 묶었으므로 사실이 아니다 —
  세 트리거를 명시하도록 갱신했다.

## 미조치 (INFO 18건)

리뷰어가 **"현재 도달 불가"** 로 확인한 것들(`client.id` 재진입 덮어쓰기 · `exp` 상한 ·
`toISOString` RangeError · `exp` 과거 입력)은 그대로 둔다. 전제(연결마다 신규 id · TTL 900초
고정 · 앞단 검증)가 바뀌면 그때 연다 — **도달 불가 경로에 방어를 쌓는 것은 검증할 수 없는
코드를 늘리는 것**이다.

3라운드 연속 지적된 셋도 판단을 유지한다: 타이머 타입 non-optional 화·메시지 상수화(취향 범위),
빈 consistency 세션(기능 무관). ~~**#11 이중 빈 줄은 이번에 정리했다**~~ — **이 문장은 거짓이었다.** 그렇게 적어 놓고
실제로는 고치지 않았고, 4R 에서 scope·maintainability 두 리뷰어가 독립적으로 잡았다
(`git show` 로 대조하면 해당 hunk 가 diff 에 아예 없다). **4R 에서 실제로 제거하고
`git diff` 로 반영을 확인했다.** 사소한 포맷팅에서 났지만, 같은 습관이 기능 항목에서
나면 위험도가 다르다 — "조치했다" 는 `git diff` 로 확인한 뒤에 쓴다.

**#7** 은 기록해 둔다: `AuthTokenExpiredPayload.expiresAt` JSDoc 이 *"클라이언트가 이 값으로
남은 창을 계산"* 한다고 적는데 실제 핸들러는 payload 를 읽지 않고 즉시 재발급한다. spec 계약은
충족하지만 **문서가 구현보다 넓다** — 다음에 이 payload 를 실제로 쓰거나 JSDoc 을 좁힐 때
정리할 자리다.

이미 등재된 것들(spec 배지 flip · 배포 전환 창 · thundering herd · e2e 유예)은 plan 에
근거·재개 신호와 함께 있다.

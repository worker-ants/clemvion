# 변경 범위(Scope) 리뷰 — filter-pg-invalid-text

## 개요

`GlobalExceptionFilter` 가 22P02 를 분류하지 않는다는 트래커 항목으로 착수했으나, 조사 결과 그 처방(필터 수정)이 spec 원칙(`3-error-handling.md §1`, `data-flow/12-workspace.md`)에 반한다고 판단해 won't-do 로 종결하고, 실제 결함(keyset 커서 id 성분이 `uuid` 컬럼에 검증 없이 바인딩되는 2곳)을 고친 배치다. 대상 파일 7개 — 코드 2쌍(서비스+spec), CHANGELOG, plan 문서 2개(신규 1 · 기존 갱신 1).

## 발견사항

- **[INFO]** plan 체크리스트 텍스트와 체크박스 상태 불일치
  - 위치: `plan/in-progress/keyset-cursor-uuid-validation.md:160`
  - 상세: `- [ ] CHANGELOG (완료 — 관측 가능한 변경 2건)` — 괄호 안에는 "완료" 라고 적어 두었는데 체크박스는 미체크(`[ ]`)다. 실제로 같은 diff 의 파일 1(`CHANGELOG.md`)에 해당 항목이 이미 반영돼 있어(behavior-change 엔트리 추가 완료), 체크박스만 실제 상태를 못 따라간 것으로 보인다. 스코프 자체의 문제는 아니지만 체크리스트가 실제 상태를 반영해야 한다는 저장소 관례(plan 체크박스 = 실제 상태)에서 어긋난다.
  - 제안: 커밋 전에 체크박스를 `[x]` 로 갱신하거나, 아직 최종 확정 전이라면 괄호 안 "완료" 표현을 지워 혼동을 없앤다.

## 스코프 준수 확인 (긍정적 관찰)

1. **의도 이상의 변경 없음**: 실 코드 변경은 `login-history.service.ts`·`background-runs.service.ts` 두 파일의 `decodeCursor` 에 `isUuidShaped` 검증 한 줄씩 추가한 것이 전부다. `GlobalExceptionFilter`(원래 트래커 항목의 처방 대상)는 조사 결과 건드리지 않기로 명시적으로 결정했고 실제로 diff 에도 없다 — 조사로 처방이 바뀌었을 때 코드를 그 결론에 정확히 맞춘 사례다.
2. **관련 결함 클래스(`#1328`, `ParseUUIDPipe`)와의 경계를 문서에서 명시**적으로 분리했다(`keyset-cursor-uuid-validation.md` 상단 "스코프 고지") — 실제로도 그쪽 코드는 손대지 않았다.
3. **불필요한 리팩토링 없음**: 두 디코더의 실패 계약(무시 vs 400)이 서로 다름에도 통일하지 않고 각자의 기존 계약을 유지한 채 id 검증만 추가했다 — "통일은 관측 가능한 동작 변경이라 별도 제품 결정" 이라는 이유를 명시하고 백로그로만 등재했다(`spec-draft-nullable-notation-followups.md` 신규 항목). 스코프를 넓히지 않으려는 의도적 절제로 판단된다.
4. **기능 확장(over-engineering) 없음**: `#1328` 은 정적 가드를 신설했지만, 이번 건은 모집단이 2곳뿐이라는 이유로 가드 신설을 명시적으로 보류하고 회귀 테스트로만 고정했다 — 과잉 엔지니어링을 피한 근거가 문서화돼 있다.
5. **임포트**: 새로 추가된 임포트는 기존 `common/utils/uuid.ts` 의 `isUuidShaped` 재사용뿐이고 즉시 사용된다. 신규 유틸 생성이나 불필요한 정리 없음.
6. **테스트 변경의 정당성**: `login-history.service.spec.ts` 의 기존 fixture(`'cursor-id'` → `CURSOR_UUID`)를 바꾼 것은 수정과 무관한 정리가 아니라, 그 fixture 자체가 결함(비-UUID 를 정상으로 고정)을 감추고 있었기 때문— 새 회귀 테스트가 그 자리를 RED 로 드러낸 사실과 주석으로 근거를 남겼다. 스코프 내 변경이다.
7. **plan 문서 갱신**: `spec-draft-nullable-notation-followups.md` 에서 원래 항목을 취소선으로 남기고 근거를 각주로 추가한 방식은 `CLAUDE.md` 가 요구하는 자기-반증형 소정정/취소선 관례와 일치한다. spec 파일(`spec/**`) 자체는 건드리지 않고 발견된 spec 갭 3건을 전부 "planner 항목" 으로만 등재해 developer 의 쓰기 권한 경계를 지켰다.
8. **설정 변경 없음**: `package.json`/`tsconfig`/CI 등 설정 파일은 diff 에 없다.
9. **CHANGELOG 내용**은 실제 코드 변경(두 엔드포인트의 처분 차이 포함)과 정확히 일치하고, 별도 무관한 서술이 섞여 있지 않다.

## 요약

이번 diff 는 트래커 항목 조사 중 처방이 바뀐 사례임에도 불구하고, 실제 코드 변경을 새 결론(입구 검증 2곳)에 정확히 국한시켰고, 원래 처방 대상(필터)·인접 결함 클래스(`#1328`)·계약 통일·가드 신설 등 스코프를 넓힐 수 있었던 지점들을 모두 의도적으로 배제하며 그 근거를 문서화했다. 포맷팅/주석/임포트 변경도 모두 실질 변경에 종속돼 있어 섞인 잡음이 없다. 발견된 유일한 항목은 plan 체크리스트의 텍스트-체크박스 불일치로, 스코프 위반이 아니라 사소한 문서 정합성 문제다.

## 그 외 확인한 항목 (문제 없음)

- `clearExpiryTimers` 추출은 `armExpiryTimers`(무장)와 `handleDisconnect`(해제) 두 소비처의 "타이머 쌍 clear + Map 삭제" 절차를 단일 헬퍼로 모아 중복을 제거한 정상적인 Extract Method다. 이전 라운드(`11_57_58`)에서 지적된 JSDoc 오귀속(architecture WARNING) — `armExpiryTimers` 헤더 JSDoc 이 `clearExpiryTimers` 로 잘못 붙은 문제 — 은 현재 파일(`websocket.gateway.ts:147-241`)에서 이미 정정되어 각 심볼이 자신의 JSDoc 을 갖고 있음을 `Read` 로 직접 확인했다.
- `expiryTimers` 맵 값 타입을 `{ notice?: …; cutoff?: … }` → `{ notice: …; cutoff: … }` 로 non-optional 화한 것은 "표현 불가능한 상태를 타입으로 제거"하는 방향이며, `handleDisconnect` 의 옛 `if (timers.notice) … if (timers.cutoff) …` 방어 분기(도달 불가능했던 죽은 코드)도 함께 사라졌다 — 가독성·복잡도 양쪽에 도움이 된다.
- `MSG_AUTH_TOKEN_EXPIRING` 상수 승격은 네이밍이 기존 `MSG_NOT_AUTHENTICATED`/`MSG_NOT_AUTHORIZED_EXECUTION` 접두 컨벤션과 일관되고, 소비처가 gateway.ts + spec.ts 둘이라는 근거로 (로컬이 아닌) `websocket-events.types.ts` 로 승격한 판단도 그 모듈이 이미 enum 을 export 하던 기존 패턴과 맞는다.
- 신규 테스트 5종(`websocket.gateway.spec.ts:795-891` 부근)은 각각 하나의 관측 가능한 동작(상수 일치, 재무장 시 옛 타이머 해제, `exp` 없는 재무장에서도 해제, 만료 tie 시 emit→disconnect 순서, unref)만을 검증하고, 왜 그 단언이 필요한지("존재만 보면 안 걸린다"류) 주석으로 명시해 가독성이 좋다. 기존 `connectWithExp` 헬퍼를 재사용해 중복도 적다.
- 함수 길이·중첩 깊이: `armExpiryTimers`(약 53줄, 중첩 최대 2단)·`handleConnection`(중첩 최대 3단, 기존 코드)은 이번 diff 범위 내에서 과도하게 길어지거나 깊어지지 않았다.

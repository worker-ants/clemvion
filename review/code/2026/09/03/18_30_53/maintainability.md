- **[INFO]** plan 문서의 체크박스 한 줄에 "확정" 결론과 원래(폐기된) 후보 목록 서술이 접속사 없이 이어붙어 가독성이 떨어짐
  - 위치: `plan/in-progress/entity-nullable-column-type-mismatch.md` (§배치 2 절, "배치 3 기준" 체크박스 항목 — `- [x] **배치 3 기준** — **"잔여 전량"으로 확정**(아래 §배치 3). 남은 것이 8필드뿐이라 축이 종결됐다. 원문 후보 검토 — 남은 축은 **"전부 안 넓혀진 6파일"**...` 로 시작하는 줄)
  - 상세: `[ ]` → `[x]` 로 바꾸면서 새 결론("잔여 전량으로 확정")을 앞에 붙이고, 그 뒤에 원래 초안이었던 "원문 후보 검토 — 남은 축은..." 문단을 그대로 이어 붙였다. 두 서술의 경계가 시각적으로 구분되지 않아(굵게 표시된 결론 문장 뒤 바로 원문이 이어짐) 다음에 이 문서를 읽는 사람이 "확정된 결론"과 "폐기된 초안 근거"를 혼동할 수 있다. 코드가 아닌 plan 문서이지만, 이 저장소는 plan 을 결정 기록의 단일 진실로 쓰므로(§체크리스트 동기화 컨벤션) 가독성 훼손이 실질적 비용이 된다.
  - 제안: 원문 후보 검토 문단을 별도 인용 블록(`>`)이나 줄바꿈으로 분리하거나, 이미 §배치 3 절에 동일 내용이 상세히 기술돼 있으므로 이 체크박스 줄에서는 "확정. 상세는 §배치 3 참조"로 간결화하는 편이 낫다.

## 요약

이번 diff 는 8개 엔티티 파일의 nullable 컬럼 타입을 `| null` 로 넓히는 기계적이고 범위가 명확한 리팩터이며, 코드 자체의 가독성·네이밍·함수 길이·중첩·매직넘버·중복·복잡도 어느 관점에서도 새로운 문제를 만들지 않았다. 특히 두 가지가 눈에 띄게 좋다: (1) `audit_log.ip_address` 에 `type: 'varchar'` 를 추가한 것이 형제 엔티티(`login-history`, `refresh-token`)의 동일 컬럼 데코레이터와 키 순서까지 정확히 일치해 일관성이 높고, (2) `folders.controller.ts` 에서 `dto as Partial<Folder>` 캐스트를 제거한 것은 `UpdateFolderDto.parentId: string | null | undefined` 가 이제 넓혀진 `Folder.parentId: string | null` 과 구조적으로 맞아떨어지면서 가능해진 것으로, 실제로 `Folder` import 도 함께 정리되어 dead import 가 남지 않았다(직접 확인함). `folders.service.spec.ts` 의 불필요해진 이중 캐스트 제거도 같은 맥락의 정리다. `@Column` 데코레이터 키 순서 통일 여부는 plan 문서에서 이미 실측(다수 형태 17 vs 10)을 근거로 won't-do 로 명시적으로 결정돼 있어 이번 diff 의 범위 밖으로 적절히 배제됐다. 유일하게 지적할 점은 plan 문서 자체의 문장 접합부 가독성으로, 코드 품질에는 영향이 없는 INFO 수준이다.

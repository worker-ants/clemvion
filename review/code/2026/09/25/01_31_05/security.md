# 보안(Security) 리뷰 — MinIO 이미지 일치 가드

## 검토 범위

- `.claude/tests/test_minio_image_parity.py` — 신규 하네스 테스트(YAML 파서 기반 이미지 참조 일치 검사)
- `plan/in-progress/minio-image-parity-guard.md` — 해당 작업의 plan 문서

두 파일 모두 CI 하네스 내부에서만 실행되는 테스트/문서이며, 외부 사용자 입력이나 네트워크 요청을 다루지
않는다. 대상 데이터는 저장소 자체에 커밋된 `docker-compose.yml` · `docker-compose.e2e.yml` ·
`k8s/overlays/local/infra-minio.yaml` 세 파일뿐이다.

## 발견사항

- **[INFO]** `_PINNED` 정규식의 ReDoS 가능성 — 정적 형태만으로는 배제할 수 없어 실측
  - 위치: `.claude/tests/test_minio_image_parity.py:77-79` (`_PINNED = re.compile(...)`)
  - 상세: `(?:[^/@\s]+/)*[^/:@\s]+:(?P<tag>[^/:@\s]+)@sha256:[0-9a-f]{64}` 형태의 정규식이다. 각
    `[^/@\s]+/` 세그먼트는 `/` 로 경계가 확정되어 모호한 분할이 발생하지 않으므로 고전적 중첩
    정량자(`(a+)+`류) 패턴은 아니지만, 프로젝트 관례("정적 형태 판단 vs 벤치마크")에 따라 실측했다.
    scratch 스크립트로 입력 길이를 2×~80× 늘려가며 4가지 적대적 입력(다수 `/` 세그먼트+콜론 없음,
    구분자 없는 긴 문자열, 콜론은 있으나 다이제스트 없음, 다수 콜론)을 매칭한 결과 매 케이스 선형
    시간(길이 4배 → 시간 약 4배, 160,001자에서도 5ms 이하)으로 스케일했다 — 지수적 백트래킹 없음을
    확인했다. 또한 이 정규식이 처리하는 문자열은 항상 저장소 내 신뢰된 YAML 파일에서 추출한 이미지
    참조 문자열이지 외부/사용자 입력이 아니므로, 설령 병리적 케이스가 있었더라도 공격 표면이 되지
    않는다.
  - 제안: 조치 불필요. 참고 기록 목적의 INFO.

## 항목별 점검 결과

1. **인젝션**: SQL/커맨드/LDAP 인젝션 표면 없음(DB·쉘 호출 없음). 경로 탐색 없음 — 파일 경로는
   `REPO_ROOT / "docker-compose.yml"` 등 모듈 수준 상수로 고정되며 사용자 입력이 개입할 지점이 없다.
2. **하드코딩된 시크릿**: 없음. 테스트 픽스처의 `"0" * 64`, `"a" * SHA256_HEX_LEN` 류 다이제스트 문자열은
   자리수를 맞춘 더미 값이며 실제 인증/암호 자료가 아니다.
3. **인증/인가**: 해당 없음 — 런타임 애플리케이션 코드가 아닌 CI 전용 테스트/문서.
4. **입력 검증**: `yaml.safe_load` / `yaml.safe_load_all` 사용(중요) — `yaml.load`(임의 파이썬 객체
   역직렬화로 인한 RCE, PyYAML의 잘 알려진 위험 패턴)를 쓰지 않고 안전한 변형을 일관되게 사용한다.
   `_dig`/`_seq`/`_expect_one`/`_image_value` 헬퍼가 예상 밖 YAML 형태(리스트가 와야 할 자리에 매핑,
   스칼라, 누락 키 등)를 전부 `{}`/`[]`/`PlaceNotFound` 로 흡수해 `AttributeError`/`TypeError`
   전파를 막는다. `pin_violation` 은 `fullmatch` 를 써 트레일링 문자로 검증을 우회할 수 없게 한다.
5. **OWASP Top 10**: 해당 코드 경로에는 웹 요청/응답, 세션, 직렬화 데이터 처리가 없어 대부분의 항목이
   비적용이다.
6. **암호화**: 해시/암호화 알고리즘을 직접 구현하지 않는다. SHA-256 다이제스트는 이미지 무결성
   고정(그 자체가 보안 강화 목적)이며 정규식은 그 형식(소문자 16진수 64자)만 검증한다.
7. **에러 처리**: `PlaceNotFound` 메시지는 파일 레이블·서비스/컨테이너 이름 등 저장소 내부 구조 정보만
   포함하며, 비밀값·스택트레이스·시스템 경로 등 민감 정보 노출은 없다.
8. **의존성 보안**: 유일한 서드파티 의존성은 PyYAML(`import yaml`)이며 안전한 API(`safe_load`)만
   사용— 알려진 위험 패턴(`yaml.load` 무제한 로더)을 회피했다.

## 요약

두 파일 모두 런타임 애플리케이션 코드가 아니라 CI 하네스 테스트와 그 작업 계획 문서로, 외부 입력·
네트워크·인증 경계를 다루지 않아 공격 표면이 사실상 없다. YAML 파싱은 `safe_load` 계열만 사용해 역직렬화
RCE 클래스를 회피했고, 정규식은 벤치마크로 선형 시간 스케일링을 확인해 ReDoS 우려도 해소했다. 하드코딩된
시크릿, 인젝션, 민감정보 노출 등 통상적 취약점 패턴은 발견되지 않았다.

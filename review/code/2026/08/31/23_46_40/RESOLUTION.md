## 가장 중요한 것 — 내가 넣은 가드가 정작 기본값 케이스를 놓쳤다 (W5)

3라운드에서 "프로덕션에 localhost 가 실리는" 실패를 막으려 부팅 경고를 넣었다. 그런데 그
경고가 볼 값을 **손으로 다시 계산**했고, 마지막 항이 SoT 와 달랐다:

```
s3.config.ts   S3_PUBLIC_BASE_URL || S3_ENDPOINT || 'http://localhost:9000'   ← 실제 서빙값
main.ts (내)   S3_PUBLIC_BASE_URL || S3_ENDPOINT || ''                        ← 경고가 본 값
```

두 env 가 **모두 미설정**이면 앱은 `http://localhost:9000` 을 서빙하는데, 경고는 `''` 를
보고 `if (publicBase && …)` 에서 걸러져 **침묵한다.** 즉 가드가 막으려던 바로 그 실패의
기본값 경로를 자기 안에 재도입했다.

규칙을 순수 함수 `resolvePublicBaseUrl(env)` 로 빼고 `s3.config.ts` 와 `main.ts` 가 공유하게
했다. `||`(falsy)를 쓰는 것도 계약으로 고정했다 — `??` 면 `S3_PUBLIC_BASE_URL=` (빈 문자열)
이 빈 base 로 통과한다. 리뷰가 두 연산자를 바꿔도 40건이 GREEN 임을 실측해 지목한 자리다.

뮤턴트 Q3(마지막 항을 `''` 로 = 원 결함 복원) → **RED 3**, Q4(`||`→`??`) → **RED 2**.

`s3.service.ts` 의 `?? endpoint` 는 그대로 뒀다 — 그쪽은 env 가 아니라 **ConfigService** 를
읽는 다른 레이어이고, 설정 모듈이 로드되지 않은 조립(부분 mock 테스트)에서 `undefined` 가
URL 에 박히는 것을 막는 2차 방어다(3라운드에서 테스트를 붙였다).

  - 위치: `.claude/tests/test_block_integrity.py:691`-`696`

(명령: `python3 -c` 로 `.claude/tests/*.py` 를 AST 파싱해 `marker`-매칭 Constant 마다 `"raise " in stub`/`"push_blocks" in stub` 를 찍는 스크립트 — 재현 가능.)

## 요약

이번 라운드(11R)에서 실행 가능한 두 가지 결함을 mutation 으로 확정했다. 가장 심각한 것은 `_shared/git_probe.py::_origin_default_branch`/`_default_branch` — 세 가드가 공유하는 "기본 브랜치 판정" 함수가 통합(9R)된 이후에도 실제 git 저장소로 구동하는 테스트를 한 번도 얻지 못했고, 모든 소비자가 이 경계를 mock 으로 우회한다. 실제 저장소에서 prefix 스트립 로직을 무력화하는 변형을 만들어 하네스 전체(9개 관련 파일 286개 테스트)를 돌렸더니 전부 GREEN 이었고, 이 결함은 review_guard/plan_guard 쪽에서는 `_merge_base` 폴백의 우연한 자기보정 때문에 증상이 가려지지만 `branch_guard` 의 핵심 정책(메인 워크트리에서 기본 브랜치 직접 편집 금지)을 조용히 무력화한다 — 정확히 이 브랜치의 과거 라운드들이 "git 헬퍼가 mock 에 가려 실행된 적이 없다"고 반복해서 찾아낸 것과 같은 클래스가, 같은 함수군 안에서 아직 한 함수만큼 남아 있다. 두 번째로, 이번 라운드가 `test_block_integrity.py` 의 스텁 검사를 파일-조인 방식에서 스텁-개별 방식으로 고치며 (정당한 개선이지만) 부수적으로 도입한 `"raise " in stub` 면제가 raise/return 이 섞인 스텁 리터럴 전체를 검사에서 제외시킨다 — 오늘은 4개 파일의 실제 스텁이 우연히 전부 `push_blocks` 를 갖고 있어 무증상이고, 그 중 하나(`test_guard_review_before_push_main.py`)는 기능 테스트가 독립적으로 같은 결함을 잡아주지만, 이 메타가드 자신의 존재 이유는 raise/return 혼합 스텁에 대해서는 더 이상 성립하지 않는다. 그 외 검토한 파일들(`review_guard.py`·`plan_guard.py`·`branch_guard.py` 의 결정 로직, `test_review_gate_ci.py` 의 배선/판정-단일성/환경-무관성 가드, `test_workflow_yaml_structure.py`)은 라운드 1R~10R 의 반복 경화를 거쳐 견고했고 이번 검토에서 새 우회를 찾지 못했다.

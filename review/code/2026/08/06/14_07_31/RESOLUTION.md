# RESOLUTION — 10R (harness-review-ci-backstop)

## C1 — 내 통합이 여섯 번째를 빠뜨렸고, 그 이유가 핵심이다

9R 에서 git 프로브 5개를 `_shared/git_probe.py` 로 통합했는데 **`_current_branch` 가 빠졌다** —
`plan_guard` 와 `branch_guard` 에 AST 동일한 사본으로 남아 있었다. 두 suite 모두 그것을
`mock.patch.object` 로 우회해 실구현을 한 번도 안 돌린다. 리뷰어가 뮤테이션으로 실증했다:
반환값을 오염시켜도 **849개 테스트 전원 GREEN** 이면서 "메인 워크트리에서 default 브랜치 편집
차단" 이라는 핵심 enforcement 가 조용히 무력화된다(두 사본 값이 우연히 같아 라이브 결함은 아님).

**왜 빠졌나가 결함보다 중요하다.** 통합도, 그것을 지키려고 9R 에 만든 가드도 **손으로 쓴
목록**(`_SHARED`)이었다. 손 목록은 빠뜨릴 수 있고, 실제로 빠뜨렸다 — 세 라운드에 걸쳐 "손-동기
쌍은 갈린다" 를 고쳐온 그 브랜치가 그것을 막는 가드를 손 목록으로 지었다.

**처분: 열거를 도출로.** 가드가 세 모듈의 AST 를 서로 비교해 **본문이 동일한 함수가 남아
있으면 그 자체로 실패**한다. 무엇이 복제됐는지 사람이 미리 알 필요가 없다.
검증 — 목록에 없던 새 함수를 두 훅에 복제하는 뮤턴트도 RED(열거 방식이면 놓쳤을 형태),
`_current_branch` 복제 부활도 RED.

## W1 — 9R 이 만든 위임 메커니즘 자체가 같은 함정이었다

`git_probe._origin_default_branch` 가 `branch_guard` 를 파일 경로로 되감아 로드하는 래퍼였고,
그 **성공 경로를 어떤 테스트도 실행하지 않았다**(3개 팀이 독립 뮤테이션으로 실증). 게다가
`bg._origin_default_branch` 를 표준 방식으로 mock 해도 실제 해석엔 반영되지 않아, 9R 이 없앤
"패치해도 무효인 가짜 seam" 이 다른 모양으로 재도입돼 있었다.

**처분: 정본을 `git_probe` 로 이관하고 `branch_guard` 가 참조한다.** 래퍼가 사라지면서
W2(`exec_module` 실패 시 `sys.modules` 영구 오염)와 W3(혼동되는 시그니처)도 **그 코드와 함께
소멸**했다. 역방향 의존도 실측으로 확인 — import·호출 후 `sys.path` 오염 0.

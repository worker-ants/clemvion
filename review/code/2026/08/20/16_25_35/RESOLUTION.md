## WARNING 2 — `hasMaskedMarkerLeaf` 에 깊이 상한이 없다 (performance) — **수정**

**전제를 먼저 실측했다** (node 24 / V8, 무수정 프로브):

| 중첩 깊이 | `JSON.parse` | 상한 없는 재귀 탐색 |
|---|---|---|
| 1,000 | OK | OK |
| **5,000** | **OK** | `RangeError: Maximum call stack size exceeded` |
| 100,000 | **OK** | 동상 |

`JSON.parse` 는 반복적 구현이라 통과시키는 깊이를 재귀 탐색이 못 따라간다. 에디터
"Run with Input" 은 사용자가 붙여넣은 임의 JSON 을 파싱해 곧바로 이 함수에 넘기고, 그
호출부는 `useMemo` = **렌더 경로**라 예외가 React 트리로 전파돼 화면이 깨진다.

> **이 저장소가 반복해 겪은 "자매 중 하나만" 이다.** backend 짝 `deepRedactCore` 에는
> `MAX_REDACT_DEPTH = 10` 이 있는데 프런트 미러에는 없었다. 미러를 만들 때 **값 집합만
> 베끼고 하드닝은 안 베낀** 것이다.

### 상한 값을 backend 와 같게 두는 근거

`deepRedactCore` 는 `depth >= 10` 에서 서브트리를 통째로 마커로 **치환**한다. 즉 backend 를
거쳐 온 값에는 depth 10 아래에 아무것도 없다 — 여기서 10 아래를 안 봐도 **놓치는 마커가
없다**(그 아래 구조는 사용자가 직접 만든 것이지 마스킹의 산물이 아니다).

> **off-by-one 이 곧 fail-open 이다.** 치환된 마커는 **depth 10 그 자리에** 있으므로
> 값 검사(`isMaskedMarker`)가 깊이 검사보다 **먼저** 와야 한다. 순서를 뒤집으면 상한
> 지점의 마커를 검사도 안 하고 지나친다.

### 2층 방어 — 에디터 호출을 try 안으로

상한이 이 표면의 **유일한** 방어가 되지 않게, `hasMaskedMarkerLeaf` 호출을 `JSON.parse` 와
같은 `try` 블록으로 옮겼다. 어떤 이유로든 던지면 "잘못된 JSON" 안내로 떨어진다.

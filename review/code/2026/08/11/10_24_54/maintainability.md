# 유지보수성(Maintainability) Review

focus: `sseErrorDetail` 헬퍼(직전 라운드 WARNING 반영분) 위치·이름·JSDoc 적절성 + `use-widget.ts` 누적 주석 밀도 판정.

## 발견사항

- **[WARNING]** `sseErrorDetail` 이 React 훅 본문 내부에 nested 되어 있는데, 들여쓰기는 module-level 함수처럼 0칸이라 실제 스코프를 오독하게 만든다 — `openStream` 의 JSDoc 과 정의 사이에 끼어 doc-code 인접성도 깨진다
  - 위치: `codebase/channel-web-chat/src/widget/use-widget.ts:459-477` (JSDoc 459-469 + 함수 본문 470-477). 인접 문맥: `:437-458`(`openStream` 을 설명하는 JSDoc) → `:459-477`(`sseErrorDetail`) → `:479`(`const openStream = useCallback(`).
  - 상세: 중괄호 깊이를 직접 세어 확인했다 — `useWidget() {` 진입 직후 depth=1 이고, `sseErrorDetail` 직전(469행)까지도 depth=1(즉 `useWidget()` 본문 스코프 안), `function sseErrorDetail(...) {` 로 depth=2 가 됐다가 `}` 로 다시 1로 복귀한다. 즉 **`sseErrorDetail` 은 `useWidget()` 훅 body 안에 nested 선언된 함수**다. 그런데 들여쓰기는 0칸(주변 훅 본문 statement 들은 전부 2칸)이라, 코드를 훑는 사람에게는 module-level top-level 함수처럼 보인다. `npx eslint src/widget/use-widget.ts` 는 클린(indent 규칙 미설정)이라 이 오배치를 자동 가드가 못 잡는다.
    더 나쁜 것은 물리적 위치다: `openStream` 을 설명하는 JSDoc(437-458행, "SSE 를 연다...")이 끝나자마자(458행 `*/`) 곧바로 `sseErrorDetail` 의 JSDoc+구현이 끼어들고, 그다음에야 `openStream` 의 실제 정의(479행 `const openStream = useCallback(`)가 나온다. `openStream` 을 이해하려고 그 JSDoc 을 읽은 독자는 곧바로 무관한 헬퍼 선언을 먼저 마주친다.
    이 파일은 이미 "클로저를 캡처하지 않는 순수 헬퍼는 `useWidget()` 위 module scope 에 둔다"는 일관된 컨벤션을 갖고 있다(`fetchEmbedConfig`, `isEmbedAllowed`, `safeApiBaseFromQuery`, `configFromQuery` 모두 33-190행 사이, `useWidget()` 정의(192행) 이전). `sseErrorDetail(e: unknown)` 도 파라미터 외 아무 클로저도 캡처하지 않는 순수 함수라 같은 자리에 둘 수 있는데도 훅 내부에 끼워 넣어 이 컨벤션과 어긋난다.
  - 제안: module scope(다른 순수 헬퍼들 옆, `useWidget()` 정의 위)로 옮기거나, SSE 에러 진단이라는 관심사가 이미 자리 잡은 `codebase/channel-web-chat/src/lib/eia-client.ts`(`EventSourceLike`/`openStream` 정의 위치, `redactToken`/`isTerminalAuthError` 도 여기 있음)로 옮기는 것을 검토. 훅 내부에 남기기로 결정한다면 최소한 `openStream` `useCallback` 콜백 바디의 `onError` 바로 앞으로 옮겨 사용 지점과 인접시키고 들여쓰기를 실제 스코프(2칸)에 맞출 것.

## 요약

`sseErrorDetail` 은 이름과 JSDoc 내용 자체는 적절하지만, **위치**가 문제다 — 클로저를 캡처하지 않는 순수 함수인데도 module scope 컨벤션을 벗어나 `useWidget()` 훅 본문 안에 nested 되어 있고, 들여쓰기(0칸)가 실제 스코프(depth=2, 즉 nested)와 어긋나 top-level 함수처럼 오독되며, 하필 `openStream` 의 JSDoc 과 정의 사이에 끼어 그 함수를 읽는 흐름을 끊는다. 누적 주석 밀도 질문에는 "이제 과하다"가 답이다 — 실측 52.9%(719/1358줄)가 주석이고 11개 서로 다른 리뷰 라운드 인시던트가 소스에 직접 인용돼 있는데, 그중 순수 가치 손실은 비율 자체가 아니라 **"`sessionRef.current` 를 읽어라"는 동일 근거가 4곳에서 전문 복제**된 부분이다 — 이 파일 스스로 이미 "위 주석 참조" 포인터 패턴(1235행)을 쓰고 있으면서 다른 3곳은 그 패턴을 안 따랐다. "가드를 한쪽에만 적용" 모티프(6회)와 뮤테이션-생존 메모(4회)는 각각 지점별 근거가 있어 당장 삭제를 요구하지는 않되, 다음 라운드가 또 늘리면 통합을 검토할 시점이다.

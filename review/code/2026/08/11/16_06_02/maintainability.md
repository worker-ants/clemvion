# 유지보수성(Maintainability) Review — 직전 라운드 INFO 처분 확인

오케스트레이터가 요청한 3개 확인 항목에 집중한다. 억지 발견 없음.

## 1. `safeApiBase` JSDoc blockquote 축약 — 정보 손실 여부

**손실 없음.** 축약 전(`99d3e9000`)의 3줄 blockquote는 "spec §R0 에서 정정했는데 코드는 안
고쳤다" 는 **자기정정 이력**을 서술했고, 그 자체가 이미 죽은 `§R0` 앵커를 인용하는 오류를 안고
있었다. 축약 후(현재, `codebase/channel-web-chat/src/widget/use-widget.ts:197-198`)는

```
> 첫 판은 "`applyConfig` 가 자기 자리에서 실패한다" 고 적었다 — **거짓이다.**
> 정정 이력은 `4-security.md` **§R7** 참고(같은 서술을 여기 되풀이하지 않는다).
```

두 줄로, "거짓이었다" 는 결론만 남기고 이력 서술은 포인터로 넘겼다. 코드를 읽는 사람이 반드시
필요한 사실 — **"진단은 `console.warn` 에만 있다"** — 은 이 blockquote 가 아니라 바로 위
문단(`use-widget.ts:192-195`, "**진단은 여기(`console.warn`)에만 있다.** ... `warn` 도
`dispatch` 도 없이 **조용히 반환**한다")에 독립적으로 남아 있어, blockquote 를 안 읽어도
확보된다. 포인터 대상인 `spec/7-channel-web-chat/4-security.md` §R7(272-306행)을 직접 열어
대조한 결과, "기각한 대안" 실측 2가지·"진단은 거절 지점에만 있다" 자기정정 문단(296-302행)
전부가 그대로 있어 링크를 따라가도 정보가 끊기지 않는다.

## WARNING #2 (testing) — 내 주석이 사실과 달랐다 → 조치

"클라이언트가 헤더를 두 번 보내면 express 가 배열을 넘긴다" 고 적었는데, 리뷰어가 raw socket
으로 중복 헤더를 실제 전송해 반증했다. **내가 다시 프로브해 확인했다:**

```
Idempotency-Key: a / Idempotency-Key: b  →  type=string  value="a, b"
Set-Cookie: c1     / Set-Cookie: c2      →  type=array   value=["c1","c2"]
```

Node `http` 는 `set-cookie` 만 배열로 두고 나머지 중복 헤더는 `", "` 로 조인한다. 즉
`typeof raw !== 'string'` 분기는 **타입이 허용하는 형태에 대한 방어**이지 중복 헤더 경로가
아니었고, **실제로 도달하는 경로(조인 문자열)는 어떤 테스트도 안 보고 있었다.**

**조치**: 주석을 실측값과 함께 정정하고, 조인 문자열(`"a, b"`)이 그대로 유효한 키가 되는
경로를 별도 테스트로 고정했다. 그 동작이 옳은 이유(결정적이므로 멱등성 성립)와, 나중에 거부
쪽으로 바꿀 때 판단 근거가 필요하다는 점도 적었다.

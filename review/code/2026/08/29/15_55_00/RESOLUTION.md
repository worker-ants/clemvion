## Warning #1 — 등재로 갈음한다 (§수렴 예외)

지적: `describe("멀티라인 링크의 깨진 타깃도 잡힌다")` 가 `fingerprint()`(kind+target)만 보고
`LinkViolation.line` 을 단언하지 않는다.

**(a) 동작 결함이 아니다.** `.line` 계약은 이미 **단위 층에서 5곳**이 잠그고 있다:

| 테스트 | 단언 |
|---|---|
| `줄 번호는 링크가 **시작한** 줄이다` | `line = 5` |
| `멀티라인 링크 2개` | `line = 3`, `line = 8` |
| `단일+멀티 혼재` | `line = 3`, `5`, `8` |
| `3줄 이상 스팬` | `line = 5` |

그리고 `findBrokenLinksInFiles` 는 `extractLinks` 가 준 `link.line` 을 **그대로 전달**한다
(변환 없음). 즉 통합 층 단언이 더할 판별력은 "전달이 끊기지 않았는가" 뿐이고, 그건 같은
객체를 넘기는 코드라 끊길 형태가 아니다. **off-by-one 회귀는 위 5개가 먼저 RED 를 낸다.**

**(b) fix 가 새 라운드를 강제한다.** `spec-links.test.ts` 는 `codebase/**` 라 한 줄만
건드려도 방금 통과한 `/ai-review`(`15_55_00`)가 freshness 로 무효가 되고, lint·unit·build·
e2e 4단계 + 리뷰 한 바퀴를 다시 돈다. **이 PR 은 이미 4라운드를 돌았다.**

**(c) 등재 사유는 비용이 아니라 수렴이다.** 라운드별 발견의 성격:

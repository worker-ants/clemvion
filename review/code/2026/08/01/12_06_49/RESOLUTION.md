## 접근이 틀렸다 — 패치가 아니라 설계 반전

세 라운드 동안 나는 "이 스크립트/워크플로에 우회가 없다" 를 **정적 부분 일치**로 증명하려 했고,
매 라운드 새 우회가 나왔다.

| 라운드 | 가드 | 무엇에 뚫렸나 |
|---|---|---|
| 1R | 전문 grep | 스크립트 자기 docstring |
| 1R | docstring 제외 grep | 자기 사용자 안내 문구 |
| 2R | 연산 금지 목록 | `pathlib.rglob`, `from os import walk as _w` |
| 2R | 호출 허용 목록 | 2단 체인, 지역 별칭, `getattr`, `__import__`, `os.popen` |
| **3R** | **앵커 없는 정규식** | **`if: … && false`** — 백스톱이 모든 PR 에서 영구히 꺼지는데 15개 전부 GREEN |

`&& false` 가 결정적이다. 그 한 줄이 이 PR 의 존재 이유를 정면으로 무효화하는데 테스트는 전부
초록이었다. 매번 "이런 우회도 있네" 로 읽고 목록을 늘린 것이 잘못이었다 — 임의 표현식에서
의미 보존을 부분 일치로 판정하는 것은 **무한한 표면**이다.

**유한한 문제로 바꿨다:**

### (1) 워크플로 배선 → 기대값 **정확 일치**

`if` · 게이트 step 의 `run` · trigger `paths` · `concurrency` 를 전부 상수로 적어두고 `==` 로
비교한다. 어떤 변경이든 실패하고, 저자는 기대값을 갱신하면서 "이게 게이트를 끄는 변경인가" 를
의식적으로 판단하게 된다. **우회할 패턴이 아예 없다.**
더해서 게이트 step 에 `if:` 키가 없음(조용한 skip 방지), checkout 은 **게이트 직전 것**만 본다
(shallow 실효 + deep decoy 조합 차단).

### (2) 판정자 단일성 → **행위** 검증

게이트를 스텁으로 두고 **종료 코드가 (스텁 판정 × `--enforce`) 의 순함수인지** 네 조합 전부
확인한다. 숨은 두 번째 판정자가 결과를 바꾸면 어떤 방식으로 숨어 있든 이 표에서 어긋난다.
`OneJudgeTest` 는 남기되 **무엇을 증명하는지 낮춰 적었다** — "두 번째 판정자가 없다" 가 아니라
"import/호출 표면이 작게 유지된다" 이다. 정적으로 닫을 수 있는 만큼만 주장한다.

한 가지는 행위 검증으로도 안 잡혔다: `sys.exit = os.system` 재바인딩이 종료 코드를 **우연히**
보존한다(`os.system(1)` 이 TypeError 로 exit 1). 리뷰어 처방대로 **속성 대입 형태 자체를
금지**했다 — 이 스크립트가 남의 속성에 대입할 정당한 이유가 없으므로 유한하고 완전하다.

## 권장 조치사항

1. `_BLOCK_AT_LINE_START`/`_BLOCK_AT_LINE_END` 의 "BLOCK:" 직후 `\s*\**\s*` 서브패턴을 단일 quantifier 구조로 재작성해 잔존 O(n²) 을 제거하고, "BLOCK: 존재 + 그 뒤 긴 공백/개행 런 + YES/NO 없음" 적대적 케이스를 서브프로세스+하드타임아웃 회귀 테스트로 추가 (Critical #1).
2. `_glob_to_regex()` 에 glob 당 `*`/`?` 총 개수 상한(예: 8개)을 두어 초과 시 스킵+stderr 경고하고, 동일한 서브프로세스+타임아웃 방식의 회귀 테스트를 추가 (Critical #2).
3. 위 두 수정 후 커밋된 SUMMARY.md 전량(1,506+)과 spec `code:` glob 전량을 재검증해 verdict/매칭 결과가 불변임을 확인.
4. `code_review_orchestrator.collect_change_infos` 의 `--branch`/`--commit`/`--range` > `--files` 침묵 우선순위를 plan 항목 #11 이 이미 제시한 최소 조치(우선순위 명시 + stderr 경고, 또는 `mutually_exclusive_group`)로 이번 기회에 해결 — 이미 "높음" 우선순위로 추적 중이며 실제 게이트 무력화 전례(6R)가 있음 (Warning #1).
5. `evaluate_review()` Gate 2 의 `notes` 배선을 mock 없이 실 데이터 경로로 end-to-end 검증하는 테스트 추가(기존 헬퍼 패턴 조합으로 낮은 비용) (Warning #6).
6. `merge_coordinator_orchestrator.py` 의 브랜치/PR ref 인자에 `--` 구분자 삽입 또는 `-` 접두 거부 검증 추가 (Warning #5).
7. (낮은 우선순위, 이미 추적 중) plan 항목 #9(`merge_coordinator` reconcile 위임)·#10(`retry_state.py` 잠금)·#3(`build_files_section` 분리)을 계획대로 진행하고, 3-orchestrator CLI 디스패치 보일러플레이트 통합(Warning #7)과 `consistency_orchestrator.py` 의 orphaned 주석(Warning #9) 정리를 병행.

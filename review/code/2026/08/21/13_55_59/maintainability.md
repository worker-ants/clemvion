# 유지보수성(Maintainability) Review — masked-marker-contract-7d2e14 (라운드 7, 13_55_59)

## 검토 범위

이 PR 은 6라운드째 리뷰(`11_27_29`~`13_34_34`)를 거치며 backend/frontend 에 손 복제돼 있던
마스킹 마커 상수·판정 로직·깊이 상한을 `@workflow/masked-markers` 공유 패키지로 추출하고, 그
이관이 되돌려지지 않는지 지키는 "미러 재발 가드"(backend·frontend 쌍둥이)를 신설했다. 직전
라운드(`13_34_34`)가 지적한 문서 비대칭(backend spec 에 "대칭 캐너리" 규칙 문단 누락)은
현재 소스(`masked-marker-mirror.spec.ts`)에 반영돼 있음을 직접 `Read` 로 확인했다. 이번
라운드는 현재 소스 상태(신규 패키지 `src/index.ts`, 쌍둥이 가드 4파일, 소비처 재export shim)를
다시 전수 열어 새로 남은 흠을 찾았다.

## 발견사항

- **[INFO]** backend spec 헤더의 "규칙" 문단이 다른 줄보다 비정상적으로 길고, 블록쿼트(`>`)
  연속이 중간에 끊겨 마지막 문장만 인용 밖으로 빠진다 — 직전 라운드(`13_34_34`)가 "함께
  정리하면 비용이 없다"고 제안했지만 반영되지 않았다
  - 위치: `codebase/backend/src/repo-guards/__tests__/masked-marker-mirror.spec.ts:36`-`37`
    (`describe('마커 SoT 미러 재발 가드 (backend)', ...)` 바로 위 JSDoc 헤더)
  - 상세: 실측(`awk '{print length}'`) 결과 이 파일에서 가장 긴 줄은 36번째 줄로 **241자**다
    — 두 번째로 긴 줄(129자)의 거의 두 배다. `* > **규칙**: 판정 분기를 새로 넣거나 고칠
    때는 **양쪽에 대칭 캐너리를 함께** 넣는다. 값의 미러와 달리 탐지 로직의 중복은
    **한쪽이 낡아도 반대쪽 트리거를 무력화하지 않는다**:` 한 줄에 두 문장을 이어 붙이면서
    줄바꿈을 하지 않았다. 게다가 바로 다음 줄(37)인 `한 사본이 낡아도 다른 사본이 같은
    불변식을 자기 트리거에서 계속 지킨다.` 는 앞 5줄(31~36)이 전부 갖고 있던 `* >` 블록쿼트
    접두사(`>`)가 없다 — 즉 이 문장만 markdown 렌더 시 인용 블록 밖으로 빠져 나가 앞
    문맥("다만 그 안전은 조건부다")과 시각적으로 끊긴 채 렌더된다. 같은 내용을 담은 frontend
    쌍둥이(`masked-marker-mirror.test.ts:39-40`, `:47`)는 이 문장을 규칙 문단보다 앞쪽
    별도 문단에 정상 줄바꿈으로 배치해 이 문제가 없다 — 즉 이번에도 "같은 정보를 양쪽에
    싣는다"는 목표는 달성했지만 그 실행 형태(줄바꿈·인용 구조)가 갈렸다. 기능적 영향은
    없다(주석/문서 전용).
  - 제안: 36번째 줄을 문장 경계에서 줄바꿈하고, 37번째 줄 앞에 `> ` 를 붙여 인용 블록을
    끝까지 유지한다(frontend `test.ts:39-40` 형태를 그대로 옮기면 된다).

- **[INFO]** frontend 미러 가드 spec 파일에 backend 쌍둥이에는 없는 이중 빈 줄이 두 곳
  남아 있다 — 기능 영향 없는 사소한 포맷 드리프트지만, 이 PR 이 "쌍둥이 파일은 동일 형태를
  유지한다"는 규율을 반복해 명시해 온 자리라 기록한다
  - 위치: `codebase/frontend/src/lib/repo-guards/__tests__/masked-marker-mirror.test.ts:69`-`70`,
    `:86`-`87` (각각 `it("[캐너리] 스캔 대상 파일 목록이 비어 있지 않다", ...)` 와
    `it("[캐너리] SoT 심볼 파생이 비지 않는다", ...)` 다음)
  - 상세: `awk` 로 연속 빈 줄을 실측한 결과 이 파일에만 두 자리에 빈 줄이 2개씩 연달아
    있고(다른 자리는 전부 1개), `codebase/backend/src/repo-guards/__tests__/masked-marker-mirror.spec.ts`
    에는 연속 빈 줄이 한 곳도 없다(동일 스캔으로 확인). Prettier/ESLint 가 이 파일 확장자에
    대해 연속 빈 줄을 강제로 접지 않는 설정으로 보이며 빌드·테스트에는 영향이 없다.
  - 제안: 두 자리의 빈 줄을 하나씩 지워 backend 쌍둥이와 형태를 맞춘다(선택 사항, 비차단).

## 요약

핵심 로직(`findRedeclaredSymbols`/`findMirrorRedeclarations`/`resolveScanDirs`/`listSourceFiles`)은
여전히 함수가 짧고 책임이 하나씩이며, 중첩도 최대 3단(for-for-if)에 그친다. 6라운드에 걸쳐
지적된 실질 결함(가드 배치의 경로 게이팅 사각지대·감시 목록 자체가 미러·스캔 범위가
"전수처럼 보이지만 아님"·완료형 서술이 거짓·문서 비대칭)은 전부 현재 소스에 반영돼 있음을
직접 확인했다. 이번 라운드에서 새로 발견한 것은 둘 다 INFO 급 문서/포맷 흠이다 — 하나는
직전 라운드가 이미 지적했으나 반영되지 않은 JSDoc 줄바꿈/블록쿼트 흠(backend spec.ts:36-37,
기능 영향 없음), 다른 하나는 frontend spec 에만 남은 이중 빈 줄 두 곳(backend 쌍둥이와
포맷이 어긋나지만 이 역시 기능 영향 없음)이다. 두 건 모두 이 PR 이 반복해 온 "쌍둥이 파일이
완전히 대칭이어야 한다"는 자기 규율에 비춰 기록할 가치는 있지만, 코드 동작·테스트 결과에는
영향을 주지 않아 병합을 막을 사유는 아니다. 신규 패키지(`@workflow/masked-markers`)의
`src/index.ts`·README·재export shim·CI/Docker 배선 8곳은 기존 컨벤션(`@workflow/ai-end-reason`
등)과 일관되고, 네이밍(`MAX_MASK_DEPTH` 중립화)·매직넘버·중복 코드 축에서 새로 지적할 사항이
없다.

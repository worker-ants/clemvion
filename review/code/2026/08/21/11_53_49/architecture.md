## 요약

핵심 설계 — 손으로 복제되던 마커 상수·깊이 상한을 `@workflow/masked-markers` 공유 패키지(순환 의존 없는 단방향 "공유 커널")로 추출하고 backend/frontend 는 재export shim 으로 소비처 import 경로를 보존한 것 — 은 견고하고, `@workflow/ai-end-reason` 선례를 그대로 따라 SOLID·결합도·레이어 책임 어느 축에서도 새 문제를 만들지 않는다. 직전 라운드(`11_27_29`)가 지적한 "미러 소멸 캐너리가 frontend vitest 에만 있어 backend-only PR 에 무력하다"는 WARNING 도 backend 사본 신설로 정확히 고쳐졌다(실측: `backend-checks.yml` pathspec 이 `codebase/backend/**` 를 포함하고 jest `testRegex` 가 `*.spec.ts` 를 잡으므로 신규 backend 스위트가 실제로 걸린다). 다만 그 수정이 두 스택(backend/frontend) 사이의 대칭만 회복했을 뿐, 두 미러 가드 자신이 `SCAN_DIRS` 로 명시 포함시킨 **세 번째 스택(channel-web-chat)** 은 `web-chat-checks.yml` 이 별도 vitest 스위트만 돌리고 어느 미러 가드 사본도 포함하지 않아 여전히 CI 사각지대에 있다 — 이 PR 이 존재하는 이유였던 바로 그 실패 클래스(CI 경로 게이팅으로 인한 가드 무력화)가 한 스택만큼 남아 있는 셈이다. 그 외 발견(감시 심볼 목록의 손-복제, 접두 문자열 자기제외 판정, 탐지 로직 자체의 스택 간 복제)은 전부 잠복 상태이거나 이미 근거 있게 트레이드오프된 사항으로 INFO 수준이다.
